# Авторинг заданий hashpass

## Обзор

Задание — это тренажёр мышления, а не диктант команд. Система ведёт себя как хороший наставник:
**спрашивает, а не отвечает**; показывает, *куда* смотреть (вывод команды, `man`, `--help`, поиск),
а не *что* набрать. Ответ студент добывает сам. В конце — шутка, чтобы было за что любить курс.

**Нарушить букву этих правил = нарушить их смысл.** Подсказка с готовой командой «для удобства»,
«потому что так в соседних заданиях», «на второй попытке уже можно» — это нарушение.

Справочник синтаксиса и рантайма — `dsl-reference.md` рядом (читать перед написанием Taskfile).

## Когда использовать

- Пишешь/переписываешь любой `content/tasks/<id>/` (Taskfile, brief.md, hp/finale).
- Добавляешь `hint`, `on enter`, `say`, формулировку `stage`, финал.
- Ревьюишь чужое задание: сверяй с контрактом ниже.
- Не для: правок движка DSL (`src/hashpass/recipe`, `taskrun`) — там обычный TDD.

## Контракт задания — что есть каждая часть

Тон: обращение на **ты**, коротко, с юмором; ключевые слова DSL — английские, всё для студента — по-русски.

| Часть | Что это | Чего в ней НЕТ |
|---|---|---|
| `stage "…"` | **Цель** в терминах результата: что должно появиться / что узнать. Пути — да. | Команды, ключей, «Этап 1/3», «наберите». |
| `brief.md` | Теория: как устроена команда, **обобщённые** примеры на *других* именах/путях/числах; раздел `## Задание` с реальными путями. Заканчивается «Нажми **Enter**». | Команды, решающей это задание; путей задания внутри примеров. |
| intro `say` | Одна фраза: контекст, настроение, повод. Потом `read brief.md`. | Инструкций. |
| `on enter` | Рамка или вопрос, который задаёт направление («В `dir2` пока пусто — что там должно оказаться?»). Может отсутствовать. | Команд, ключей, «просто наберите». |
| `hint output "…"` / `hint cmd …` | Реакция на **естественную ошибку**: указание прочитать вывод («cp сам сказал, чего не хватило») или вопрос. Ставится **выше** `tries`. | Названия ключа, команды. |
| `hint tries N` | Лестница: **вопрос → куда смотреть → понятие** (см. умолчания). Каждая ступень срабатывает один раз. | Готовой команды с путями. Ни на какой ступени. |
| `hint idle N` | «Долго сидишь»: перечитай цель и вывод последней команды. | Ответа. |
| `hp/finale` | `#!/bin/sh` + `cat <<'ART'`: ASCII-мем или шутка + одна строка-мораль. | «Отлично, молодец» без прикола. |
| Среда | `run` создаёт файлы/каталоги/пакеты **при сборке**; нужный инструмент установлен (`run apt-get install -y …`), иначе `command not found` — не задание, а баг. | «Искусственных» действий ради приёмки (лишний redirect в файл, когда результат и так виден). |

Приёмка — по **результату** (`observe`/`check`/`accept cmd`), и любым способом (`variant`), а не
по совпадению с эталоном.

## Лестница подсказок — умолчания

| Ступень | Условие | Форма |
|---|---|---|
| реактивная | `hint output "<точный фрагмент ошибки>"`, `hint cmd <base> missing <флаг>` | «Прочитай, что ответила команда: …» / вопрос по выводу |
| 1 | `hint tries 3` | Наводящий вопрос («Что ты ждёшь увидеть в X? Проверь, что там сейчас.») |
| 2 | `hint tries 6` | Источник: `man <cmd>` + слово для поиска внутри, `<cmd> --help`, «загугли: …» |
| 3 | `hint tries 10` | Только для сложных этапов: понятие или *имя* ключа («нужен ключ рекурсии»). Не команда. |
| долго | `hint idle 240` | «Перечитай цель и последний вывод» |

Простое задание (одна очевидная команда, прямо из теории: `whoami`, `ls`, `man man`, `--help`) —
**одна** ступень-вопрос на `tries 4` или **ни одной**. Три ступени — для многошаговых и «с подвохом»
(скрытые файлы, рекурсия, порядок аргументов `find`, права).

Точные фрагменты ошибок (локаль C): `omitting directory`, `Is a directory`, `paths must precede
expression`, `No such file or directory`, `Permission denied`, `Operation not permitted`,
`Unable to locate package`, `command not found`.

## Пример: было → стало (`cp-more`, скопировать каталог целиком)

```
# БЫЛО — ответ до первой попытки, точная команда на второй
  on enter say "cp с последним аргументом-директорией копирует туда все предыдущие."
  hint tries 2 say "Подсказка:  cp -r /home/student/dir1/. /home/student/dir2/"
  hint idle 30 say "Ключ -r (recursive) даёт cp повторить обход дерева."

# СТАЛО — вопрос, вывод, источник; ключ по имени — только на 10-й попытке
  on enter say "В dir2 пока пусто. После твоей команды там должно лежать всё то же, что в dir1."
  hint output "omitting directory" say "Прочитай ответ cp целиком: он сам сказал, чего ему не хватило."
  hint tries 3 say "Загляни в dir2: что там оказалось? Всё, что было в dir1, или только часть?"
  hint tries 6 say "man cp — найди слово recursive. Или загугли: «cp скопировать каталог со всем содержимым»."
  hint tries 10 say "Каталог — не файл; cp обходит его только с ключом рекурсии. Какая это буква — ты уже знаешь."
  hint idle 240 say "Долгая пауза. Перечитай цель и вывод последней команды — ответ обычно там."
```

Финал не «cp -r — рекурсивный копир», а шутка: `«Копия неотличима от оригинала. Как и твой дипломный проект»`.

## Рационализации, которые НЕ принимаются

| Отговорка | Реальность |
|---|---|
| «Так во всех соседних заданиях» | Соседние переписаны по этому skill. Старый стиль — ошибка, а не образец. |
| «Это единственная новая мнемоника, стоит дать сразу» | Мнемоника живёт в `brief.md`, на обобщённом примере. `on enter` — вопрос. |
| «На второй попытке уже можно конкретику» | Вторая попытка — это ещё не думал. Вопрос на 3-й, источник на 6-й, понятие на 10-й. |
| «Без точной команды студент не пройдёт» | Пройдёт: вывод, `man`, поиск. Если этап непроходим без ответа — сложность не та, перепиши этап, а не подсказку. |
| «Подсказка с командой, но “в общем виде” (`tar -czf <архив> <каталог>`)» | Это команда с плейсхолдерами. Не проходит. |
| «Финал — просто похвала» | Финал — мем/шутка. Похвала без прикола не выполняет требование. |
| «`hint idle 30` — чтобы не скучал» | 30 секунд — это он ещё читает вывод. Минимум 180–240. |

## Red flags — остановись и перепиши

- В `say`/`hint` есть слово «Наберите», «Точно:», «Подсказка:  <команда>», путь задания рядом с именем команды.
- `hint tries 1` / `tries 2`.
- `on enter` содержит имя ключа (`-r`, `-a`, `-czf`) или команду.
- `brief.md` содержит команду решения с путями *этого* задания.
- Сообщение `stage` начинается с «Запустите»/«Наберите» или содержит «Этап N/M».
- Финал без шутки.

## Процесс

1. Прочитай `dsl-reference.md`; посмотри 1–2 уже переписанных задания как образец тона.
2. Напиши `Taskfile` + `brief.md` + `hp/finale` (`chmod +x`).
3. Парсинг: `python3 -m pytest tests/content/test_bundled_taskfiles_parse.py -q`.
4. Сборка: `cd content/tasks/<id> && hashengine build Taskfile` (деривация в nspawn).
5. Живая проверка `expect`-ом по реальной консоли (`hashpass run <id>:1`): неверная команда ×3 →
   на экране вопрос; ещё ×3 → источник; верная → финал; подсказка **не повторяется** на `ls`.
   Без этого прогона «работает» не говорить (memory `verify-with-expect-before-delivery`).
6. Один коммит на задачу/пачку. На пул (`hashengine push`) — только по явной просьбе.
