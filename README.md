# hashpass

hashpass — платформа для интерактивных заданий и лабораторных по Linux. Автор описывает задание в
одном текстовом файле (DSL), из него собирается образ-контейнер, а студент решает задание в живой
консоли настоящей системы Debian (`systemd-nspawn` + `overlayfs`). Приёмка невидимая и идёт на
хосте: после каждой команды система сверяет состояние ФС/вывод с эталоном, выведенным из авторского
решения. Прогресс студентов собирается на общем **пуле** и виден преподавателю в веб-панели.

## Два инструмента

- **`hashpass`** — для **студента**. Ставится одной командой с сайта пула, привязывается к нему,
  подтягивает задания и запускает их. Ничего авторского в себе не несёт.
- **`hashengine`** — для **автора/преподавателя**: собрать образ (`build`), опубликовать задание в
  пул под номером (`push --task N`), поднять сам пул с веб-панелью (`serve`). Это привилегированный
  инструмент: он активируется только через `make install` или установку с сайта пула (с ролью
  автора), поэтому на обычной студенческой машине не работает.

## Пул

`hashengine serve` поднимает пул — сетевой сервис: реестр образов/заданий, аутентификация с ролями
(студент/автор/админ), регистрация студентов (обязательны ФИО и группа), нумерованный каталог
заданий, серверный учёт passed/failed по каждому студенту, проверка целостности задания и
серверная веб-панель прогресса для преподавателя. Пул сам отдаёт установщик — адрес пула студенту
вводить не нужно.

## Как работает у студента

1. Установка одной командой (её показывает главная страница пула):
   ```bash
   curl -fsSL https://<адрес-пула>/install.sh | bash
   ```
   Скрипт ставит `hashpass` и запоминает адрес пула. При первом запуске — регистрация (логин, ФИО,
   группа) или вход.
2. `hashpass` без аргументов — параллельно (многопоточно) подтягивает новые задания из каталога и
   показывает их по номерам с отметкой пройденных.
3. `hashpass run <номер>` — задание открывается как настоящая консоль. По прохождению всех этапов
   результат уходит на пул; целостность задания проверяется по хэшу (подменённое задание зачёта не
   даёт).

Оба инструмента при запуске проверяют новые версии на GitHub и обновляются сами.

## Как работает у автора

```bash
make install                                  # ставит и активирует hashengine
cd content/tasks/showcase
hashengine build Taskfile                      # собрать задание (спросит логин один раз)
hashengine serve                               # поднять пул (реестр + веб-панель)
hashengine push <логин>/showcase:1 --task 1 --title "Первое задание"   # опубликовать под №1
```
Преподаватель заходит в веб-панель пула (`/web`), видит таблицу «студенты × задания» с отметками
пройденного, фильтрует по группам, а админ управляет пользователями и открывает/закрывает
регистрацию.

## Требования

- Python 3.13.
- `systemd-nspawn` (пакет `systemd-container`) + `overlayfs` — чтобы **запускать** задания.
- Базовый rootfs Debian — файл `<home>/base/rootfs.tar`, готовится **один раз вручную** (например
  `docker export debian:trixie-slim -o rootfs.tar` на любой машине, или debootstrap) и кладётся на
  место. hashpass его сам не строит и docker в зависимостях не имеет.
- Scoped passwordless sudo на: `mount`, `umount`, `systemd-nspawn`, `rsync`, `tar`, `machinectl`.
- Пул (`hashengine serve`) — чистый stdlib, без зависимостей; за TLS/публичный адрес отвечает
  reverse-proxy оператора.

## Установка

- Студент — с сайта пула (см. выше). Данные и кэш в `~/.hashpass`.
- Автор — `make install` (ставит обе команды и активирует `hashengine`); `make uninstall` — удалить.
- Без установки: `python3 -m hashpass <команда>` / `python3 -m hashengine <команда>`.
