# Код возврата, if и проверки

Скрипт без условий — просто список команд. Чтобы он реагировал («архив битый — сообщи», «файла
нет — создай»), ему нужно спрашивать. В bash спрашивают **код возврата**.

## Код возврата

Каждая команда, завершаясь, отдаёт число: `0` — успех, всё остальное — ошибка. Код последней
команды — в `$?`:

```
$ ls /etc > /dev/null; echo $?
0
$ ls /nope; echo $?
ls: cannot access '/nope': No such file or directory
2
$ gzip -t site-2026-09-11.tar.gz; echo $?

gzip: site-2026-09-11.tar.gz: unexpected end of file
1
```

Что значат ненулевые коды, написано в `man программы`, раздел EXIT STATUS. `$?` меняется после
**каждой** команды — даже после `echo`, поэтому его сохраняют сразу: `rc=$?`.

## if, && и ||

`if` запускает команду и выбирает ветку по её коду:

    if grep -q root /etc/passwd; then
        echo есть
    else
        echo нет
    fi

Коротко то же — `&&` («если успешно, то») и `||` («если нет, то»):

```
$ grep -q root /etc/passwd && echo есть || echo нет
есть
```

Осторожно: `a && b || c` — не полный `if`. Если упадёт сама `b`, выполнится и `c`.

## [ ] — команда-проверка

Спросить о файлах, строках и числах помогает команда `[` (она же `test`). Это **команда**, а не
скобка, поэтому пробелы обязательны:

```
$ [-s site-2026-09-01.tar.gz ]
bash: [-s: command not found
```

И её не нужно ставить вокруг другой команды:

```
$ if [ gzip -t site-2026-09-01.tar.gz ]; then echo ok; fi
bash: [: -t: binary operator expected
```

| Проверка | Истина, когда |
|---|---|
| `-e путь` | существует |
| `-f путь` / `-d путь` | обычный файл / каталог |
| `-s путь` | файл есть и не пустой |
| `-r` `-w` `-x` | можно читать / писать / запускать |
| `-z "$s"` / `-n "$s"` | строка пустая / не пустая |
| `"$a" = "$b"`, `!=` | строки равны / не равны |
| `a -eq b`, `-ne -gt -ge -lt -le` | сравнение **чисел** |
| `! проверка` | наоборот |

### Ловушка: пустая переменная без кавычек

```
$ x=""; [ $x = yes ] && echo да
bash: [: =: unary operator expected
$ x=""; [ "$x" = yes ] || echo нет
нет
```

Без кавычек пустая `$x` исчезла, и `[` получил `= yes`. В кавычках — пустая строка, всё честно.

### Ловушка: `>` внутри [ ]

```
$ [ 9 > 10 ] && echo «9 больше 10»; ls
«9 больше 10»
10
site-2026-09-01.tar.gz
...
```

`>` — перенаправление: команда `[ 9 ]` (всегда истина) записала пустой вывод в файл `10`. Числа
сравнивают `-gt`:

```
$ [ 9 -gt 10 ] || echo «9 не больше 10»
«9 не больше 10»
```

## [[ ]] и (( ))

Это не команды, а синтаксис самого bash — поэтому в них можно больше:

```
$ [[ site-2026-09-01.tar.gz == *.tar.gz ]] && echo архив
архив
$ [[ 9 > 10 ]] && echo «по алфавиту 9 после 10»
«по алфавиту 9 после 10»
$ (( 9 > 10 )) || echo «а по числам — нет»
«а по числам — нет»
```

- `[[ ]]`: переменные можно не брать в кавычки, есть шаблоны (`== *.tar.gz`), регулярки (`=~`),
  `&&` и `||` внутри. Но `>` и `<` в нём сравнивают **строки**.
- `(( ))`: арифметика, `>` `<` `==` — настоящие числовые сравнения.
- `[ ]` есть в любом `sh`, `[[ ]]` и `(( ))` — только в bash (и zsh, ksh). Скрипт с `#!/bin/sh`
  их не поймёт.

## case — много вариантов по шаблону

```
$ case site.tar.gz in *.zip) echo zip ;; *.tar.gz|*.tgz) echo tar ;; *) echo непонятно ;; esac
tar
```

## Размер файла

```
$ s=$(stat -c %s site-2026-09-01.tar.gz); echo $s; [ $s -gt 50000 ] && echo большой
72658
большой
```

## Где это пригодится

- Скрипт резервного копирования проверяет, что архив создался и не пустой, — иначе шлёт тревогу.
- Скрипт установки спрашивает `command -v docker` прежде, чем ставить docker.
- `grep -q`, `systemctl is-active -q`, `ping -c1 -W1` — «молчаливые» команды для условий.
