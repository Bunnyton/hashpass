# Права доступа и chmod

Почему один файл ты читаешь, а другой — нет? Почему скрипт не запускается, хотя лежит прямо
перед тобой? Это **права**: у каждого файла и каталога записано, кто что с ним может делать.
Меняет их `chmod` (change mode). Короткая таблица — на [странице-шпаргалке](wiki/cheatsheet.md).

## Как читать права в ls -l

    $ ls -l memo.txt
    -rw-r----- 1 anya anya 0 Nov  4 02:14 memo.txt

Первый символ — тип: `-` файл, `d` каталог, `l` символьная ссылка. Дальше три тройки:

    -  rw-  r--  ---
       │    │    └─ остальные (other)
       │    └────── группа файла (group) — здесь anya
       └─────────── владелец (user) — здесь anya

`r` — читать, `w` — писать, `x` — запускать; `-` — права нет. Система смотрит **одну**
тройку: ты владелец — тройку владельца; нет, но состоишь в группе файла — тройку группы;
иначе — тройку остальных.

## Права цифрами

Каждое право — один бит, у бита свой вес: `r` = 4, `w` = 2, `x` = 1. Сложи — и тройка стала
цифрой от 0 до 7. Три тройки — три цифры:

    $ chmod 754 t; ls -l t
    -rwxr-xr-- 1 anya anya 0 Nov  4 02:14 t
    $ chmod 401 t; ls -l t
    -r-------x 1 anya anya 0 Nov  4 02:14 t
    $ chmod 0 t; ls -l t
    ---------- 1 anya anya 0 Nov  4 02:14 t

Обратно — так же: `r-x` = 4+0+1 = 5. Узнать цифры готового файла поможет `stat`:

    $ stat -c '%a %A %n' memo.txt
    711 -rwx--x--x memo.txt

Менять права может только **владелец** файла (и root). Даже если сейчас у владельца нет
вообще никаких прав — `chmod` ему всё равно доступен.

## Права у каталога значат другое

Для каталога `r` — увидеть список имён, `w` — создавать, удалять и переименовывать файлы в
нём, `x` — войти в каталог и обращаться к файлам по имени. Проверим на каталоге `vault` с
одной запиской:

    $ chmod 000 vault; ls -ld vault
    d--------- 2 anya anya 60 Nov  4 02:14 vault
    $ ls vault
    ls: cannot open directory 'vault': Permission denied
    $ cd vault
    bash: cd: vault: Permission denied

Только `x` — список не прочесть, но файл по точному имени открыть можно:

    $ chmod 100 vault
    $ ls vault
    ls: cannot open directory 'vault': Permission denied
    $ cat vault/note.txt
    код от сейфа: 1234

Только `r` — имена видно, а внутрь не попасть:

    $ chmod 400 vault
    $ ls vault
    note.txt
    $ cat vault/note.txt
    cat: vault/note.txt: Permission denied

Поэтому каталогам почти всегда дают `r` вместе с `x`.

## Запуск скрипта: нужны r и x

Скрипт — текстовый файл. Без права `x` его не запустить:

    $ ls -l hello.sh
    -rw-rw-r-- 1 anya anya 50 Nov  4 02:14 hello.sh
    $ ./hello.sh
    bash: ./hello.sh: Permission denied

Но одного `x` скрипту мало: запускает его интерпретатор (`/bin/sh`), а он должен файл
**прочитать**:

    $ chmod 100 hello.sh; ls -l hello.sh
    ---x------ 1 anya anya 50 Nov  4 02:14 hello.sh
    $ ./hello.sh
    /bin/sh: 0: cannot open ./hello.sh: Permission denied

С `r` и `x` всё работает:

    $ chmod 754 hello.sh; ./hello.sh
    Привет из скрипта

Обратное тоже верно: хочешь, чтобы что-то **не** запускалось, — забери у этого `x`.
У скомпилированной программы (не скрипта) хватает одного `x`.

## Относительная запись — буквами

Когда нужно не задать все права заново, а поправить пару битов, пишут буквами:
кому (`u` владелец, `g` группа, `o` остальные, `a` все), что сделать (`+` добавить,
`-` забрать, `=` задать ровно), какие права:

    $ ls -l memo.txt
    -rw-r----- 1 anya anya 0 Nov  4 02:14 memo.txt
    $ chmod g+w,o+r memo.txt; ls -l memo.txt
    -rw-rw-r-- 1 anya anya 0 Nov  4 02:14 memo.txt
    $ chmod u=rw,go= memo.txt; ls -l memo.txt
    -rw------- 1 anya anya 0 Nov  4 02:14 memo.txt
    $ chmod +x memo.txt; ls -l memo.txt
    -rwx--x--x 1 anya anya 0 Nov  4 02:14 memo.txt

`+x` без буквы — «всем», но с поправкой на umask (о нём — в шпаргалке). Цифрами яснее,
каким станет результат; буквами — что именно меняешь. Потренироваться в обоих —
[злая цепочка прав](/web/wiki/bunnyton/chmod-evil).

## Где это пригодится

- скачал скрипт — `chmod +x`, иначе не запустится;
- ключ SSH: `~/.ssh/id_ed25519` должен быть закрыт от всех, кроме тебя, — иначе `ssh`
  откажется им пользоваться;
- общий каталог для группы, закрытые настройки с паролями, сайт, который веб-сервер должен
  читать, но не менять.
