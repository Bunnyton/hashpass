# Copy-on-write — копирование при записи

Если бы fork честно копировал память, запуск каждой команды из bash копировал бы весь bash, а
сервер с гигабайтом данных тратил бы гигабайт на каждого рабочего. На деле fork почти
бесплатный — за счёт хитрости:

1. память делится на **страницы** по 4 КБ;
2. fork не копирует страницы, а даёт копии доступ к тем же самым и помечает их «только для
   чтения»;
3. пока оба процесса только читают — страница одна на двоих, хоть на сто процессов;
4. как только кто-то пишет в страницу, ядро тихо делает её копию — уже личную для писавшего.

Это и есть **copy-on-write** (COW): копия делается только при записи и только тех страниц,
в которые писали. Поэтому у всех clone по 256 МБ в RES, а службе нужно намного меньше.

Сколько памяти у процесса действительно своей, ядро пишет в `/proc/<PID>/smaps_rollup`:

    Rss             то же, что RES: всё, что видно процессу
    Pss             своя доля: общие страницы делятся поровну между всеми, кто их видит
    Shared_Dirty    изменённые страницы, которые он делит с другими
    Private_Dirty   страницы, которые он изменил и которые есть только у него
