# Свой образ

Готовые образы — `nginx`, `postgres`, `python` — кто-то когда-то собрал. Свою программу ты
тоже упаковываешь в образ: внутрь кладёшь её саму и всё, что ей нужно для работы. Такой образ
запустится одинаково у тебя, у коллеги и на сервере — ради этого всё и затевалось.

## Dockerfile

Образ собирают по рецепту — текстовому файлу `Dockerfile`. Каждая строка — инструкция:

    FROM debian              # от какого образа отталкиваемся
    RUN apt-get install -y curl   # выполнить команду при сборке
    COPY app.sh /app.sh      # положить файл с машины в образ
    CMD ["sh", "/app.sh"]    # что запускать в контейнере

- **FROM** — основа. Никто не собирает систему с нуля: берут готовый образ и добавляют своё.
- **RUN** — команда, которая выполнится **во время сборки**; её результат останется в образе.
- **COPY** — файлы с твоей машины внутрь образа.
- **CMD** — что делает контейнер, когда его запускают по имени образа.

Рецепт — обычный текст, поэтому его хранят в git рядом с кодом: любой, кто склонирует проект,
соберёт ровно такой же образ.

## Сборка

Собрать образ с именем `myapp` из каталога `~/project`, где лежит `Dockerfile`:

    docker build -t myapp ~/project

`-t` — имя нового образа, последний аргумент — каталог с рецептом и файлами для него.
Готовый образ появится в `docker images`.
