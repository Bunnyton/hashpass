# Шпаргалка по Dockerfile

← [Свой образ: Dockerfile и docker build](../wiki.md)

| Инструкция | Что делает | Пример |
|---|---|---|
| `FROM` | основа — готовый образ, от которого отталкиваемся | `FROM debian:trixie` |
| `RUN` | команда **при сборке**, результат остаётся в образе | `RUN apt-get update && apt-get install -y curl` |
| `COPY` | файлы из контекста сборки в образ | `COPY app.py /app/` |
| `ADD` | как COPY, но умеет распаковать архив и скачать URL — без нужды не бери | `ADD site.tar.gz /www/` |
| `WORKDIR` | текущий каталог для следующих инструкций и для контейнера | `WORKDIR /app` |
| `ENV` | переменная окружения в образе | `ENV LANG=C.UTF-8` |
| `ARG` | переменная только на время сборки (`--build-arg`) | `ARG VERSION=1.0` |
| `EXPOSE` | пометка «программа слушает этот порт» — сама порт не открывает | `EXPOSE 80` |
| `USER` | от какого пользователя работать дальше | `USER app` |
| `CMD` | команда по умолчанию при `docker run образ` | `CMD ["python3", "app.py"]` |
| `ENTRYPOINT` | постоянная часть команды; CMD становится её аргументами | `ENTRYPOINT ["ping"]` |

## Две формы CMD

    CMD ["sh", "/app.sh"]      exec-форма: запускается как есть, без оболочки — так и пиши
    CMD sh /app.sh             shell-форма: обёрнута в /bin/sh -c, сигналы получает sh

В exec-форме кавычки только двойные — это JSON.

## docker build: ключи

| Ключ | Что делает |
|---|---|
| `-t имя[:тег]` | имя образа; тег по умолчанию — `latest` |
| `-f путь` | Dockerfile не в корне контекста или с другим именем |
| `--no-cache` | собрать всё заново, без кэша |
| `--progress=plain` | печатать сборку целиком, с выводом команд RUN |
| `--target ступень` | собрать только до указанной ступени (многоступенчатая сборка) |
| `--build-arg X=1` | значение для `ARG X` |

## .dockerignore

Файл рядом с Dockerfile: что **не** отправлять в контекст сборки. Синтаксис похож на
`.gitignore`:

    .git
    node_modules
    *.log

Меньше контекст — быстрее сборка, и секреты не попадут в образ случайно.
