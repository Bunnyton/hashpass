# Всё одним файлом

В README магазина — три команды, которые нужно набирать в правильном порядке и с правильными
ключами. Забыл сеть — витрина не видит склад. Перепутал порт — не открывается сайт. На
сервере таких команд десятки.

**Docker Compose** решает это так: все контейнеры проекта описаны в одном файле, а поднимает
их одна команда.

## Как описать проект

1. Файл называется `compose.yaml` и лежит в каталоге проекта.
2. Начни его строкой `services:` — дальше идёт список контейнеров. Каждый контейнер здесь
   называется **сервисом**.
3. Под `services:` с отступом напиши имя сервиса и двоеточие.
4. Ещё глубже — его настройки: `image` — из какого образа, `ports` — какие порты
   опубликовать, `environment` — переменные окружения. Это те же ключи `docker run`, только
   записанные полями.

Пример — сайт и база:

    services:
      web:
        image: nginx
        ports:
          - "8000:80"
      db:
        image: postgres
        environment:
          POSTGRES_PASSWORD: secret

Это формат YAML. Два правила:

- вложенность — отступами из **пробелов**, не табов; у соседних полей отступ одинаковый;
- элемент списка — строка, начинающаяся с `- `.

## Как запустить

1. Перейди в каталог, где лежит `compose.yaml`: compose ищет файл в текущем каталоге.
2. Подними всё, что в нём описано:

    docker compose up -d

3. Посмотри, что работает: `docker compose ps`.

Ключ `-d`, как и у `docker run`, уводит сервисы в фон. Без него compose остаётся в консоли и
печатает их журналы, пока сервисы работают, — то есть всегда.

## Сеть — сама

Сеть для сервисов compose создаёт сам и подключает к ней всех. Внутри неё каждый сервис
доступен остальным по **имени сервиса** — как контейнер по имени в своей сети.
