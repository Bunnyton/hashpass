# Куда делся ключ

Ключа нет, и это не ошибка. Что произошло, по шагам:

1. База записала ключ в файлы **внутри контейнера**.
2. Ты удалил контейнер — его файлы удалились вместе с ним.
3. Новый контейнер получил новую, чистую файловую систему из образа. Ключа там никогда не было.

Для данных, которые должны пережить контейнер, у docker есть **тома** (volumes). Два вида:

    -v /home/me/blog:/www         каталог машины (bind mount): ты сам выбираешь,
                                  где лежат файлы
    -v pgdata:/var/lib/postgresql/data
                                  именованный том: место на диске выбирает docker, ты знаешь
                                  только имя

Для баз берут именованный том — вот почему:

1. Не нужно думать о путях и правах на машине.
2. При первом запуске с новым именем тома docker сам его создаст.
3. Следующий контейнер с тем же томом получит те же данные.

Списки и подробности — `docker volume ls` и `docker volume inspect <имя>`.

Кстати, образ redis сам просит том для `/data`. Если не дать ему имя, docker создаст
безымянный — в `docker volume ls` это длинный хеш. Данные там лежат, но новый контейнер их не
найдёт: он получит новый безымянный том.
