# Слои

Образ — это не один большой архив, а **стопка слоёв**. Каждая инструкция Dockerfile, которая
меняет файлы (FROM, COPY, RUN), добавляет сверху новый слой, и в нём лежит только то,
что эта инструкция изменила:

    слой 3   RUN apt-get install python3     + /usr/bin/python3 и библиотеки
    слой 2   COPY app.py /app/               + /app/app.py
    слой 1   FROM debian                     вся система Debian

Сверху слои складываются в одну файловую систему: контейнер видит их как обычный `/`. Сам
контейнер добавляет ещё один, свой, тонкий слой поверх — туда пишется всё, что программа
меняет во время работы. Слои образа при этом не трогаются, поэтому из одного образа можно
запустить сто контейнеров.

## Зачем так сложно

- **Место.** Десять образов на основе `debian` хранят Debian один раз: нижний слой у них общий.
- **Скачивание.** `docker pull` качает только тех слоёв, которых на машине ещё нет — обновление
  программы весом в мегабайт не тянет за собой всю систему заново.
- **Скорость сборки.** Docker помнит, из какой инструкции и каких файлов получился каждый слой.
  Если ничего не поменялось, слой берётся готовым из **кэша** — в выводе сборки это `CACHED`.

## Посмотреть слои

    docker history myapp

Сверху — последний слой. `CREATED BY` — инструкция, которая его сделала, `SIZE` — сколько
он добавил. Слои с размером `0B` — это настройки вроде `CMD`: файлов они не меняют.

Ключ `--progress=plain` у `docker build` печатает сборку целиком, со всем выводом команд — видно,
какие шаги выполнялись, а какие взяты из кэша.
