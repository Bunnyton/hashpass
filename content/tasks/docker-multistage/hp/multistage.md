# Сборка в две ступени

Инструменты нужны, чтобы **сделать** сайт, но не чтобы его **показывать**. А всё, что попало
в образ на любом шаге Dockerfile, в нём и остаётся. Даже `RUN rm` в конце не поможет: слой с
инструментами уже лежит ниже, а новый слой лишь прячет файлы.

Поэтому Dockerfile делят на **ступени**. Как это устроено:

1. В одном Dockerfile может быть несколько `FROM`. Каждый `FROM` начинает новую ступень — с
   чистого образа, без всего, что было выше.
2. Первой ступени дают имя: `FROM <образ> AS <имя>`. Это мастерская: здесь ставят
   инструменты и собирают результат.
3. Следующая ступень начинается со своего `FROM` и берёт из мастерской только готовые файлы:
   `COPY --from=<имя> <путь в мастерской> <путь здесь>`.
4. Образом становится **последняя** ступень. Мастерская остаётся в кэше сборки, а в образ не
   попадает — ни инструменты, ни исходники.

Пример — программа на C: компилятор нужен только в мастерской.

    FROM debian AS build              # ступень-мастерская: всё для сборки
    RUN apt-get install -y gcc
    COPY hello.c /src/
    RUN gcc -o /src/hello /src/hello.c

    FROM debian                       # итоговый образ — чистый
    COPY --from=build /src/hello /usr/local/bin/hello
    CMD ["hello"]
