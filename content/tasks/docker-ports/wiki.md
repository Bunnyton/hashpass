# Проброс портов глубже

Как опубликовать порт, ты уже знаешь по [docker-web](/web/wiki/bunnyton/docker-web):
`-p 8080:80` — слева порт машины, справа порт внутри контейнера. Здесь — что бывает, когда
контейнеров много, кто может к ним подключиться и как отдать выбор порта самому docker.

## Колонка PORTS

Что куда проброшено, видно в `docker ps`. Читается слева направо, как путь запроса:

    $ docker ps --filter name=mytest- --format 'table {{.Names}}\t{{.Ports}}'
    NAMES         PORTS
    mytest-web2   127.0.0.1:18070->80/tcp
    mytest-web1   0.0.0.0:18080->80/tcp, [::]:18080->80/tcp

`0.0.0.0` — все IPv4-адреса машины, `[::]` — то же для IPv6. Без `->` (просто `6379/tcp`) —
порт внутри контейнера есть, но наружу не опубликован.

Для одного контейнера то же покажет `docker port`:

    $ docker port mytest-web1
    80/tcp -> 0.0.0.0:18080
    80/tcp -> [::]:18080

## Порт контейнера повторяется, порт машины — нет

У каждого контейнера своя сеть, поэтому порт 80 внутри может слушать хоть сотня контейнеров
сразу. А порт **машины** один на всех — кто занял первым, тот и держит:

    $ docker run -d --name mytest-web2 -p 18080:80 nginx:alpine
    33972ea7efb7f09eb1326e83606a41e8abe56074ee9ab3937183d97161d6c1a5
    docker: Error response from daemon: failed to set up container networking: driver failed programming external connectivity on endpoint mytest-web2 (2347eb2857afe0552f8d644516572a75b777f90e56272802be143c34cee1f2a2): Bind for 0.0.0.0:18080 failed: port is already allocated

Значит, правая часть `-p` у всех может быть одинаковой, а левая — у каждого своя:

    контейнер 1: 80  ← машина 8080
    контейнер 2: 80  ← машина 8070

Контейнер, которому не хватило порта, docker создал, но не запустил:

    $ docker ps -a --filter name=mytest- --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
    NAMES         STATUS                  PORTS
    mytest-web2   Created
    mytest-web1   Up Less than a second   0.0.0.0:18080->80/tcp, [::]:18080->80/tcp

Его имя занято, пока его не удалить, — так что после ошибки сначала убери неудачника.

## Кто может подключиться: адрес в -p

У `-p` есть третья, необязательная часть — **адрес машины**, на котором слушать. Она пишется
первой:

    -p 8080:80              все адреса: подключится любой, кто видит машину в сети
    -p 127.0.0.1:8080:80    только loopback: подключиться можно лишь с самой машины

`127.0.0.1` (localhost) — адрес «сам себе», снаружи до него не дотянуться. Проверить, кто на
каком адресе слушает, можно и без docker — `ss -ltn`:

    $ ss -ltn 'sport = :18070 or sport = :18080'
    State  Recv-Q Send-Q Local Address:Port  Peer Address:Port
    LISTEN 0      4096       127.0.0.1:18070      0.0.0.0:*
    LISTEN 0      4096         0.0.0.0:18080      0.0.0.0:*
    LISTEN 0      4096            [::]:18080         [::]:*

Так прячут всё служебное — базы, админки, метрики, черновики: к ним ходят с самой машины или
через неё (SSH-туннелем). Поменять проброс у работающего контейнера нельзя — только убрать
его и запустить новый.

**Граблей тут много:** база с `-p 5432:5432` на сервере в интернете открыта всему миру, и
docker сам прописывает правила в iptables — мимо `ufw`. Поэтому для служебного — всегда
`127.0.0.1:` в начале.

## Пусть порт выберет docker

Можно вообще не называть порт машины: у `docker run` есть ключ, который публикует все порты
контейнера (те, что объявлены в образе через `EXPOSE`) на **случайные свободные** порты машины —
обычно с 32768 и выше. Найдёшь его в `docker run --help`, в строках про publish. Какой порт
достался, покажут `docker ps` и `docker port`.

Номер меняется при каждом запуске, поэтому так делают опыты и тесты, а людям порт всегда
называют явно.
