# Сайт в контейнере

Чаще всего в контейнерах живут **серверы** — программы, которые запускаются и работают
непрерывно, пока их не остановят: сайт, база данных, чат-бот. Контейнер для них удобен: нужная
версия сервера со всеми настройками поднимается одной командой и так же одной командой
исчезает, не оставив следов в системе.

## Фон: запустил — и консоль снова твоя

Сервер не заканчивает работу сам, поэтому важно, *как* его запустить:

1. `docker run <образ>` — контейнер работает **в консоли**: она ждёт, пока он закончится.
   Сервер не заканчивается никогда, а Ctrl+C он внутри контейнера может и не услышать —
   командная строка не вернётся. Здесь консоль такой запуск сервера просто не выполнит.
2. `docker run -d <образ>` — контейнер уходит **в фон** (`-d` — detach, «отцепить»): docker
   печатает его ID и сразу возвращает командную строку. Сервер работает дальше.
3. `docker ps` — проверить, что он работает: это список запущенных контейнеров.

    docker run -d busybox sleep 600       # пример: контейнер, который просто спит 10 минут
    docker ps                             # вот он, в списке

## Порты

На одной машине может работать много серверов сразу. Чтобы соединение попало к нужному, у
каждого свой **порт** — номер от 1 до 65535, как номер квартиры в доме. Сайты по традиции
слушают порт **80**, база PostgreSQL — 5432. Веб-сервер внутри контейнера тоже слушает
порт **80**.

Адрес `http://localhost:3000` читается так:

1. `http://` — говорим с сайтом;
2. `localhost` — «эта машина»;
3. `:3000` — порт 3000 на ней.

## Как открыть сайт

- Браузером прямо в консоли — `carbonyl` (выход — Ctrl+C):

    carbonyl http://localhost:3000

- Сырую страницу, без картинок и скриптов, покажет `curl http://localhost:3000`.

Консоль делит сеть с твоим компьютером: то, что открывается в ней на `localhost`, откроется и
в обычном браузере на компьютере по тому же адресу.
