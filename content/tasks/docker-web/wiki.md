# Сайт в контейнере: фон и проброс порта

Чаще всего в контейнерах живут **серверы** — программы, которые работают, пока их не
остановят: сайт, база данных, бот. Нужная версия сервера со всеми настройками поднимается
одной командой и так же одной командой исчезает, не оставив следов в системе.

## Фон: ключ -d

Сервер сам не заканчивается. Запустишь его просто `docker run <образ>` — консоль будет ждать
его конца вечно, а Ctrl+C процесс внутри контейнера может и не услышать. Поэтому серверы
запускают **в фоне**: `-d` (detach, «отцепить»). Docker печатает длинный ID контейнера и сразу
отдаёт командную строку:

    $ docker run -d --name mytest-nap busybox sleep 300
    52953ef98f8dfcd491f56fb9069273018fb8b61ca4c053ea859c0f8789170409

Работает ли он — смотрят в `docker ps`, а что он пишет — в `docker logs`:

    $ docker logs mytest-site | tail -2
    172.17.0.1 - - [03/Nov/2026:23:21:01 +0000] "GET / HTTP/1.1" 200 121 "-" "curl/8.14.1" "-"
    172.17.0.1 - - [03/Nov/2026:23:21:02 +0000] "GET /nope HTTP/1.1" 404 153 "-" "curl/8.14.1" "-"

Это журнал веб-сервера: кто пришёл, за какой страницей и что получил (200 — отдал, 404 — нет
такой). Если сайт не открывается, первым делом смотрят сюда.

## Порты

На одной машине много серверов, и соединение находит нужный по **порту** — номеру от 1 до
65535, как номер квартиры в доме. Сайты по традиции слушают 80 (https — 443), PostgreSQL —
5432, SSH — 22. Адрес `http://localhost:3000` читается так: `http://` — говорим с сайтом,
`localhost` — эта машина, `:3000` — порт 3000 на ней.

## Проброс порта: -p

У контейнера **своя сеть**: его порт 80 снаружи не виден. Чтобы до сервера достучаться,
порт **публикуют** при запуске — `-p порт_машины:порт_контейнера`:

    $ docker run -d --name mytest-web1 -p 18080:80 nginx:alpine
    ae35e17dae8a97199308fdf3030f2adb714f18a31242b7df872890c46f8c6bc3
    $ curl -s http://localhost:18080/ | grep '<title>'
    <title>Welcome to nginx!</title>

Путь запроса: браузер → машина:18080 → docker → контейнер:80. Что куда проброшено, видно в
колонке PORTS у `docker ps`:

    0.0.0.0:18080->80/tcp, [::]:18080->80/tcp

Грабли:

- **Порт машины ниже 1024** без root не открыть — бери 3000, 8080, 8888…
- **Порт уже занят** кем-то на машине — бери другой, любой свободный.
- **Работающему контейнеру порт не добавить** — только новый контейнер с нужным `-p`.
- Ключи — **до** имени образа. `docker run nginx -p 8080:80` отдаст `-p` самому nginx.

Подробнее о портах — в [docker-ports](/web/wiki/bunnyton/docker-ports).

## curl и браузер

`curl` показывает страницу **как есть** — текст, который прислал сервер. Браузер ещё и
выполняет JavaScript, а он может дописать на страницу то, чего в исходнике не видно:

    $ curl http://localhost:18088/
    <p id="x"></p>
    <script>document.getElementById("x").textContent = "Сегодня " + new Date().getFullYear();</script>

curl видит пустой абзац и скрипт; браузер покажет «Сегодня 2026». Браузер прямо в консоли —
`carbonyl http://localhost:3000` (выход — Ctrl+C), а консоль делит сеть с твоим компьютером:
тот же адрес откроется и в обычном браузере.

## «Спрятано» в исходнике — не спрятано

Иногда строку в скрипте кодируют в **base64** и раскодируют в браузере функцией `atob()`.
Это не шифр, а просто запись байтов буквами — раскодировать может кто угодно:

    $ echo -n "секрет" | base64
    0YHQtdC60YDQtdGC
    $ echo 0YHQtdC60YDQtdGC | base64 -d
    секрет

Мораль для своих сайтов: всё, что ушло в браузер, читает любой посетитель. Пароли на
страницу не кладут ни открытыми, ни «закодированными».

## Остановить и поднять снова

Остановленный контейнер не пропадает: он лежит на диске с теми же портами и именем, и
`docker start` поднимет его снова. Как остановить — подскажет `docker --help`.
