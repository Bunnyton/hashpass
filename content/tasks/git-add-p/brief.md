# Один коммит — одна мысль

Хороший коммит делает **одно дело**: починил баг, добавил функцию, переименовал файл.
Тогда его легко понять, отменить (`git revert`) или перенести в другую ветку
(`git cherry-pick`), не прихватив лишнего.

Но работа так не делится: начал одно, отвлёкся на другое — и в файле две правки вперемешку.

Посмотреть, что изменилось на диске, ты умеешь:

    git diff               # все правки, ещё не в индексе
    git diff --cached      # то, что уже в индексе и уйдёт в коммит
