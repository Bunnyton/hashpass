# Поправить последний коммит: git commit --amend

Закоммитил и тут же заметил: файл забыл, в сообщении опечатка, коммит записан не на то
имя. Пока коммит **не отправлен** на сервер, новый «исправляющий» коммит не нужен:
последний коммит можно переделать.

## Как работает --amend

1. Готовишь исправление как обычно: правишь файлы, `git add`.
2. `git commit --amend` берёт последний коммит, добавляет к нему содержимое индекса и
   ставит **новый коммит на его место**.
3. git открывает редактор с прежним сообщением. Менять его не нужно — ключ `--no-edit`.
   Нужно новое сообщение — `-m "…"`.

Пример: в коммит не попала картинка.

    $ git log --oneline
    a18b460 Страница контактов
    $ git status --short
    ?? map.png
    $ git add map.png
    $ git commit --amend --no-edit
    [main 3e5a164] Страница контактов
     Date: Sat Nov 7 14:46:01 2026 +0300
     2 files changed, 2 insertions(+)
     create mode 100644 index.html
     create mode 100644 map.png
    $ git log --oneline
    3e5a164 Страница контактов

Коммит один, как и был, но хеш другой: `a18b460` → `3e5a164`. Старый коммит не стёрт —
на него больше не указывает ветка, а `git reflog` его помнит.

## Почему нельзя править отправленное

Напарники уже получили старый коммит `a18b460`. Если заменить его у себя, истории
разойдутся: `git push` откажет, а `git push --force` перезапишет историю на сервере у всех.
Правило простое: **amend — только для того, что ещё не ушло на сервер**.

## Имя и почта автора

Каждый коммит хранит автора. Git берёт его из настроек `user.name` и `user.email`, а
настройки лежат в нескольких местах:

| Файл | Команда | Для чего |
|---|---|---|
| `~/.gitconfig` | `git config --global …` | все твои репозитории |
| `.git/config` | `git config …` | только этот репозиторий |

Если имя есть в обоих, **побеждает репозиторий**. Кто где что записал:

    $ git config --list --show-origin | grep user
    file:/home/lena/.gitconfig	user.name=Лена Котова
    file:/home/lena/.gitconfig	user.email=lena@studio.local
    file:.git/config	user.email=intern@studio.local

Здесь в репозитории осталась почта стажёра — и все коммиты уйдут с ней. Убрать:

    git config --unset user.email

Где это пригодится: рабочая и личная почта. На рабочем проекте — `git config user.email
ты@компания.ru` (без `--global`), чтобы личная почта не утекла в историю компании.

## Автор не меняется при amend

`--amend` меняет содержимое и сообщение, но **автора оставляет прежним** — он записан,
когда коммит создали впервые. Чтобы git взял автора из текущих настроек, нужен ключ
`--reset-author`; задать любого — `--author="Имя <почта>"`.

## Шпаргалка

| Что не так в последнем коммите | Как поправить |
|---|---|
| забыл файл | `git add файл` → `git commit --amend --no-edit` |
| опечатка в сообщении | `git commit --amend -m "новое сообщение"` |
| лишний файл | `git rm --cached файл` → `git commit --amend --no-edit` |
| не тот автор | поправить `user.email` → `git commit --amend --no-edit --reset-author` |

Старый коммит, а не последний, правят [интерактивным rebase](/web/wiki/bunnyton/git-squash).
