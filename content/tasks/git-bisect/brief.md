# Поиск делением пополам

Калькулятор заказов считает неверно: `./test.sh` ругается на скидки. Год назад, в версии
`v1.0`, всё работало. С тех пор — триста коммитов. Читать их подряд — день работы.

## Приём «угадай число»

Спроси про середину:

1. Посмотри коммит посередине истории.
2. Тест там проходит — поломка в правой, более новой половине. Не проходит — в левой.
3. Возьми эту половину и снова спроси про её середину.

Каждый вопрос отбрасывает половину: из 300 коммитов виновник найдётся за 8–9 проверок.

## git bisect

Это `git bisect`. Ты называешь плохую точку и хорошую, а git сам ставит каталог на коммит
посередине и спрашивает: «а здесь?» По шагам:

1. Начни поиск:

    git bisect start

2. Скажи, где плохо, — например, в текущем коммите:

    git bisect bad

3. Скажи, где было хорошо, — коммит или тег:

    git bisect good v2.3

4. git переключился на середину. Проверь этот коммит и ответь `git bisect good` или
   `git bisect bad`.
5. Повторяй шаг 4. Когда останется один коммит, git напишет `… is the first bad commit` —
   это и есть виновник.
