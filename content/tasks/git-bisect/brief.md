# Поиск делением пополам

Калькулятор заказов считает неверно: `./test.sh` ругается на скидки. Год назад, в версии
`v1.0`, всё работало. С тех пор — триста коммитов. Читать их подряд — день работы.

Но есть приём, знакомый по игре «угадай число»: спроси про середину. Если на середине
истории тест проходит — поломка в правой половине, если нет — в левой. Каждый вопрос
отбрасывает половину: из 300 коммитов виновник найдётся за 8–9 проверок.

Это `git bisect`. Ты называешь плохую точку и хорошую, а git сам ставит каталог на коммит
посередине и спрашивает: «а здесь?»

    git bisect start            # начать поиск
    git bisect bad              # здесь плохо (текущий коммит)
    git bisect good v2.3        # а здесь было хорошо
    # …git переключился на середину: проверь и скажи good или bad…

Когда останется один коммит, git напишет: `… is the first bad commit` — это и есть
виновник.
