# Ветки

Представь: сайт работает, им пользуются люди. Тебе нужно добавить новый раздел, а это
день-два работы, и всё это время код наполовину готов. Править рабочую версию прямо так —
значит сломать сайт посреди дня. А коллеге в это же время надо срочно поправить опечатку.

Для этого есть **ветки**. Ветка — отдельная линия истории. В ней можно спокойно коммитить
сколько угодно, а основная ветка `main` остаётся рабочей, пока новое не готово. Каждый
в команде делает свою задачу в своей ветке, а готовое вливают в `main`.

Ветка в git дешёвая: это просто метка с именем, которая указывает на последний коммит линии.
Создаётся мгновенно, места почти не занимает — поэтому ветки заводят на каждую мелочь.

    git branch               # список веток, текущая — со звёздочкой
    git switch -c feature    # создать ветку feature и перейти в неё
    git switch main          # вернуться в main

Коммиты делаются в ту ветку, в которой ты стоишь. При переключении git меняет файлы в
каталоге на версию из той ветки — не пугайся, если что-то «пропало»: оно в другой ветке.
