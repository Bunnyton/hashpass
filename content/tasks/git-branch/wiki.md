# Ветки, слияние и первый конфликт

Сайт работает, им пользуются люди, а тебе нужно добавить раздел — это день-два работы.
Править рабочую версию прямо так — сломать сайт посреди дня. Поэтому новое делают в
**ветке**: отдельной линии истории, где можно спокойно коммитить, пока `main` остаётся
рабочей.

## Ветка — это просто метка

Ветка в git — подвижная метка с именем, которая указывает на последний коммит своей линии.
Новый коммит — метка сдвигается на него. Создаётся ветка мгновенно и почти не занимает места,
сколько бы файлов ни было в проекте, — поэтому ветки заводят на каждую мелочь.

`HEAD` — указатель «где ты сейчас»: обычно он смотрит на ветку, и новые коммиты попадают
именно в неё.

## Создать и переключиться

    $ git branch
    * main
    $ git switch -c cocoa
    Switched to a new branch 'cocoa'
    $ git branch
    * cocoa
      main

Текущая ветка — со звёздочкой. `git switch -c имя` создаёт ветку и сразу переходит в неё;
просто `git switch имя` — переходит в существующую. В старых инструкциях встретишь
`git checkout -b имя` и `git checkout имя` — это то же самое, `switch` новее и понятнее.

## Файлы меняются вместе с веткой

Закоммитим в `cocoa` новую строку и переключимся туда-обратно:

    $ git switch main
    Switched to branch 'main'
    $ cat drinks.txt
    Чай
    Кофе
    Сок
    $ git switch cocoa
    Switched to branch 'cocoa'
    $ cat drinks.txt
    Чай
    Кофе
    Какао
    Сок

Ничего не пропало: при переключении git кладёт в каталог версию файлов из той ветки.
Незакоммиченные правки git переносит с собой, а если они мешают переключению — откажется и
предложит сначала закоммитить или [отложить](/web/wiki/bunnyton/git-stash).

## Слияние

Готовую ветку **вливают**: переходят в ту, что принимает, и называют вливаемую —
`git merge имя`. Если в принимающей ветке ничего нового не было, git просто сдвинет её вперёд
(fast-forward). Если было — сделает коммит слияния с двумя родителями.

Пока ты работал, коллега закоммитил в `main` свою строку — **в то же место**:

    $ git log --oneline --graph --all --decorate
    * 55040a5 (HEAD -> main) Морс
    | * bba3fda (cocoa) Какао
    |/
    * 77a44c2 Напитки

## Конфликт — это вопрос, а не ошибка

    $ git merge cocoa
    Auto-merging drinks.txt
    CONFLICT (content): Merge conflict in drinks.txt
    Automatic merge failed; fix conflicts and then commit the result.

Обе ветки поменяли одно место, и git не угадывает, чья правка важнее. Он записал в файл оба
варианта:

    $ cat drinks.txt
    Чай
    Кофе
    <<<<<<< HEAD
    Морс
    =======
    Какао
    >>>>>>> cocoa
    Сок

Сверху (`HEAD`) — твоя текущая ветка, снизу — вливаемая. `git status` в это время говорит, что
делать:

    Unmerged paths:
      (use "git add <file>..." to mark resolution)
    	both modified:   drinks.txt

Как разобрать:

1. Открой файл, найди метки.
2. Оставь то, что должно получиться: один вариант, другой или оба в нужном порядке.
3. Удали строки `<<<<<<<`, `=======`, `>>>>>>>` — целиком.
4. `git add файл` — так git узнаёт, что конфликт решён.
5. `git commit` — сообщение слияния git подставит сам.

Результат в дереве:

    *   3979645 (HEAD -> main) Merge branch 'cocoa'
    |\
    | * bba3fda (cocoa) Какао
    * | 55040a5 Морс
    |/
    * 77a44c2 Напитки

Испугался посреди слияния — `git merge --abort` вернёт всё как было до него.

## Уборка

Влитая ветка больше не нужна: `git branch -d имя` удалит метку (коммиты остаются в истории).
Невлитую ветку `-d` удалить откажется — это защита; `-D` удалит насильно.

    $ git branch -d cocoa
    Deleted branch cocoa (was bba3fda).
