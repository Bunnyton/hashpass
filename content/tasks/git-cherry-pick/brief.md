# Взять один коммит

У покупателей работает версия 1.0 — ветка `release/1.0`. Разработка тем временем ушла
вперёд в `main`: там новые функции, черновики и одно важное исправление. Через загрузку
файлов можно записать файл куда угодно на сервере — достаточно назвать его `../что-то`.

Вливать `main` в релиз нельзя: вместе с исправлением приедет всё недоделанное. Нужен
**один** коммит.

## cherry-pick

`git cherry-pick` берёт изменения одного коммита и повторяет их в текущей ветке новым
коммитом — с тем же сообщением и автором, но со своим хешем. По шагам:

1. Найди хеш нужного коммита. Как найти его среди многих, ты уже знаешь: `git log` умеет
   показывать коммиты другой ветки (`git log main`), только те, что меняли файл
   (`git log -- файл`), или те, в чьём сообщении есть слово (ищи в `git log --help`
   ключ *grep*).
2. Встань в ветку, куда переносишь коммит.
3. Назови `git cherry-pick` хеш:

    git cherry-pick 1a2b3c4     # повторить здесь изменения коммита 1a2b3c4
