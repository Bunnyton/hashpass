# Хуки на сервере

Хуки бывают не только у тебя в `.git/hooks`, но и у репозитория на сервере — того, куда
делают `git push`. Серверный репозиторий **голый** (bare): в нём только история, без рабочего
каталога, поэтому его хуки лежат прямо в `hooks/` внутри него.

## Что происходит при push

1. Ты делаешь `git push`.
2. Сервер запускает `pre-receive` — до приёма. Код выхода не 0 — push отклонён целиком.
3. Сервер принимает новые коммиты.
4. Сервер запускает `post-receive` — push уже принят, можно что-то сделать с новым кодом.

Серверный хук — такой же исполняемый скрипт. Запускает его git, и запускает внутри
репозитория: команды git в хуке работают с ним без всяких путей.

## Выложить ветку в каталог

У голого репозитория нет своих файлов — только история. Выложить ветку в обычный каталог
умеет `git checkout`, если сказать ему, где рабочий каталог:

    git --work-tree=/var/www/blog checkout -f main     # файлы ветки main → в /var/www/blog

Разберём по частям:

1. `--work-tree=…` — каталог, куда класть файлы.
2. `checkout main` — файлы какой ветки класть.
3. `-f` — перезаписать, что там лежит.
