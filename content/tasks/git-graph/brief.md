# История деревом

Когда веток несколько, обычный `git log` путает: он показывает только ветку, в которой ты
стоишь, и выстраивает коммиты в одну колонку. Где что отросло и что куда влили — не видно.

## Как нарисовать дерево

1. По строке на коммит — уже знакомый ключ:

       git log --oneline

2. Добавь `--graph` — git нарисует слева линии веток:

       git log --oneline --graph

3. Добавь `--all` — в рисунок попадут **все** ветки, а не только текущая:

       git log --oneline --graph --all

## Как читать дерево

Свежие коммиты сверху, старые снизу. Пример из другого проекта:

    * 41c0a2e Тесты для поиска
    | * 9d3f1b7 Кнопка «Поиск»
    |/
    *   c52e8aa Влил login
    |\
    | * 7b10e44 Форма входа
    |/
    * 03d9c1f Первая версия

1. `*` — коммит, справа хеш и сообщение.
2. `|` — линия ветки, она идёт вниз к своим старым коммитам.
3. `|/` — **развилка**: здесь ветка отошла. Коммит под этим знаком — тот, от которого она
   отросла (в примере `9d3f1b7` отросла от `c52e8aa`).
4. `|\` над коммитом — **слияние**: у коммита `c52e8aa` два родителя, в него влили ветку.
5. В терминале рядом с хешами в скобках стоят имена веток: `(HEAD -> main)` — где ты сейчас.
