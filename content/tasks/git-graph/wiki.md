# История деревом: git log --graph

Пока ветка одна, история — прямая цепочка. Появились ветки — история стала деревом: линии
расходятся (развилки) и сходятся (слияния). Обычный `git log` этого не показывает: он видит
только ветку, в которой ты стоишь, и строит всё в одну колонку.

## Рисуем дерево

Пример — план огорода: ветка `water` уже влита в `main`, ветка `fence` — ещё нет.

    $ git log --oneline --graph
    * 96b2cc0 Грядки: укроп
    *   ab80a68 Merge branch 'water'
    |\
    | * 96adfac Полив: шланг
    | * 92c0e67 Полив по средам
    * | 7e36110 Грядки: лук
    |/
    * 09d63a9 Грядки: морковь
    * dd6f4ed Первая версия

`--graph` нарисовал линии, но `fence` в рисунке нет — её коммиты не входят в `main`.
Добавляем `--all` (все ветки) и `--decorate` (имена веток у коммитов; в терминале они видны и
без него):

    $ git log --oneline --graph --all --decorate
    * 96b2cc0 (HEAD -> main) Грядки: укроп
    | * 7eb2c32 (fence) Забор: план
    |/
    *   ab80a68 Merge branch 'water'
    |\
    | * 96adfac (water) Полив: шланг
    | * 92c0e67 Полив по средам
    * | 7e36110 Грядки: лук
    |/
    * 09d63a9 Грядки: морковь
    * dd6f4ed Первая версия

## Как читать

- Свежие сверху, старые снизу. Каждая `*` — коммит.
- `|` — линия ветки, она тянется вниз к своим более старым коммитам.
- `|/` — **развилка**: линия ветки упирается в коммит под ней. В примере `fence` отросла от
  `ab80a68`, а `water` когда-то — от `09d63a9`.
- `|\` над коммитом — **слияние**: у этого коммита два родителя.
- `(HEAD -> main)` — где ты сейчас; `(fence)` — куда указывает ветка.

Родителей коммита можно спросить и прямо:

    $ git log -1 --format='%h  родители: %p'
    e7f63eb  родители: 96b2cc0 7eb2c32

Тот же вопрос «от чего отросла» git умеет решать и сам: `git merge-base A B` печатает
ближайшего общего предка двух веток. А `git branch --no-merged` перечислит ветки, которые
ещё не влиты в текущую:

    $ git branch --no-merged
      fence

## Свои команды: алиасы

Три ключа каждый раз — долго. git разрешает завести свою короткую команду — **алиас**:

    $ git config --global alias.last "log -1 --stat"
    $ git last
    commit 96b2cc0d745eb44f0e41f3b61c86a22879278777
    Author: Аня <anya@example.com>
    Date:   Mon Oct 5 11:20:00 2026 +0300

        Грядки: укроп

     plan.txt | 1 +
     1 file changed, 1 insertion(+)

Алиас записывается в `~/.gitconfig`, в раздел `[alias]`, и работает в любом репозитории:

    [alias]
    	last = log -1 --stat

Всё, что набрано после алиаса, git допишет в конец: `git last README.md`. Список алиасов —
`git config --get-regexp alias`. Алиас с `!` в начале запускает уже не git, а команду шелла.

## Слияние в дереве

Слияние делают из ветки, **которая принимает**: перешёл в неё и назвал вливаемую. git
открывает редактор для сообщения слияния — сохрани и выйди. После слияния `fence` дерево
сходится:

    *   e7f63eb (HEAD -> main) Merge branch 'fence'
    |\
    | * 7eb2c32 (fence) Забор: план
    * | 96b2cc0 Грядки: укроп
    |/
    *   ab80a68 Merge branch 'water'

Если в принимающей ветке с момента развилки ничего не появилось, git просто передвигает её
вперёд — **fast-forward**, без коммита слияния и без развилки на рисунке:

    $ git merge idea
    Updating 3c84d32..9d10176
    Fast-forward
     f.txt | 1 +
     1 file changed, 1 insertion(+)

## Полезное рядом

- `git log --first-parent` — только «основная линия»: слияния без коммитов внутри веток.
- `git log --oneline --graph main fence` — дерево только двух нужных веток.
- `tig` и `gitk` — то же дерево в отдельной программе, с прокруткой и поиском.
