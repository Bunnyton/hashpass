# Зачем нужен git

## Знакомая картина

    диплом.docx
    диплом_v2.docx
    диплом_v2_исправленный.docx
    диплом_финал.docx
    диплом_финал_точно_финал.docx

Так выглядит «контроль версий» вручную. Через неделю уже не вспомнить, чем v2 отличается от
финала, какой файл отправили научруку и где был тот удачный абзац, который потом удалили.

С программами всё ещё хуже:

- файлов сотни, и правка в одном ломает другой;
- вчера всё работало, сегодня нет — **что именно поменялось?**
- над проектом работают десять человек одновременно — как собрать их правки вместе и не
  затереть чужие?

Система контроля версий решает это: она хранит **историю** проекта. Каждое сохранённое
состояние лежит в ней навсегда, с подписью — кто, когда и зачем поменял. К любому состоянию
можно вернуться, любые два — сравнить построчно.

## Как к этому шли

**diff и patch** (1970-е). Программа `diff` показывает, какие строки отличаются в двух
файлах, а `patch` применяет эти отличия к другой копии. Правки стали пересылать письмами
в виде «патчей».

**RCS, CVS, Subversion** (1982–2000). Историю хранит **центральный сервер**. Программист
забирает с него файлы, правит и отправляет обратно. Сервер упал или нет сети — ни истории, ни
сохранения.

**git** (2005). Ядро Linux пишут тысячи людей по всему миру, и центральный сервер с этим не
справлялся. Проект пользовался платной системой BitKeeper, но в 2005 году бесплатную лицензию
отозвали. Тогда Линус Торвальдс, автор Linux, за пару недель написал свою систему — git. Главная
идея: **полная история лежит у каждого**. Сервер нужен только чтобы обмениваться правками,
а коммитить, смотреть историю и сравнивать версии можно без сети.

Сегодня git пользуется почти любой программист, а GitHub и GitLab — это сайты, где хранят
git-репозитории и работают над ними вместе.

## Главные слова

- **Репозиторий** — каталог проекта, у которого git ведёт историю. Сама история лежит в
  скрытом подкаталоге `.git`. Удалишь его — каталог снова станет обычным, файлы останутся.
- **Коммит** (commit) — сохранённый снимок проекта: состояние файлов на этот момент плюс
  автор, время и сообщение «что сделано». Коммиты выстраиваются в цепочку: у каждого есть
  предыдущий.
- **Сообщение коммита** — короткая фраза для людей: «Исправил расчёт скидки», а не «правки».
  Через полгода по этим фразам ты будешь искать, где что меняли.

Коммит — не автосохранение. Его делают, когда закончен **осмысленный кусок** работы: добавил
функцию, исправил ошибку. Поэтому историю потом можно читать как рассказ о проекте.

git работает с любыми текстовыми файлами — не только с кодом. Конфиги сервера, скрипты,
заметки, даже эта теория — всё можно держать в git.
