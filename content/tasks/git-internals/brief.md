# Как git хранит данные

Под капотом git — склад **объектов** в `.git/objects`. Всё, что ты коммитишь, лежит там.

## Как объект получает имя

1. git берёт содержимое — файла, каталога или коммита.
2. Считает от него хеш **SHA-1**: 40 шестнадцатеричных знаков, вроде
   `3b18e512dba79e4c8300dd08aeb37f8e728b8dad`.
3. Кладёт содержимое в склад под этим именем.

Поменяй в файле одну букву — хеш станет совсем другим. Поэтому одинаковое содержимое всегда
даёт один и тот же объект, а подделать историю незаметно нельзя.

## Четыре типа объектов

    blob     содержимое одного файла (без имени!)
    tree     каталог: список имён, и у каждого — хеш blob или вложенного tree
    commit   снимок: хеш корневого tree, автор, дата, сообщение и хеш родителя
    tag      аннотированный тег

## Как заглянуть в объект

1. Возьми хеш объекта — хватит первых 7 знаков.
2. Спроси тип:

    git cat-file -t 3b18e51     # тип объекта

3. Выведи содержимое:

    git cat-file -p 3b18e51     # содержимое в читаемом виде

Вместо хеша годится и имя: `HEAD` — текущий коммит, `HEAD:docs/a.txt` — файл в нём.
