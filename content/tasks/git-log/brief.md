# История

Главная польза git видна, когда что-то сломалось. История отвечает, **что** поменялось,
**кто** поменял, **когда** и **зачем** (это написано в сообщении коммита). Вместо «вчера
работало» ищешь коммит, после которого перестало.

## Хеш — имя коммита

У каждого коммита есть **хеш** — длинное шестнадцатеричное имя вроде `3f9c2e1d…`. Его не
выдумывают, а вычисляют:

1. git берёт содержимое коммита: файлы, автора, время, сообщение и хеш предыдущего коммита.
2. Из всего этого он считает хеш.
3. Поменяй хоть букву — получится другой хеш.

Поэтому историю нельзя незаметно подделать, а хеш однозначно называет коммит на любой машине.
Для команд git хватает первых семи символов.

## Как читать историю

1. Посмотри список коммитов, от новых к старым:

       git log
       git log --oneline      # по строке на коммит

2. Нужна история только одного файла — назови его: `git log notes.txt`.
3. Покажи один коммит целиком — что и где в нём поменялось:

       git show 3f9c2e1

   Строки с `-` — как было, с `+` — как стало.

## История — не машина времени

Коммиты в git не удаляют и не переписывают задним числом: на них уже могли опираться другие
люди. Ошибку исправляют **новым** коммитом поверх — так в истории видно и саму ошибку, и её
исправление.
