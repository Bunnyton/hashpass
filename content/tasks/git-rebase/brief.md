# Перенос ветки

Ты сделал ветку `search` с поиском, пока команда продолжала работать в `main`. Теперь
`search` растёт от старой версии main, а в main уже четыре новых коммита:

    A---B---C---D---E      main
         \
          X---Y---Z        search

## Слить или перенести

Слить можно и так — `git merge` склеит линии **коммитом слияния**. Но в истории проекта
с десятком людей такие склейки превращаются в паутину. Поэтому многие команды договариваются:
в main история прямая, а ветку перед слиянием **переносят** на свежий main.

## Как работает перенос

Перенос делает `git rebase`. По шагам:

1. git находит, где ветка отошла от той, на которую её переносят (на рисунке — коммит B).
2. Откладывает в сторону коммиты ветки после этой точки: X, Y, Z.
3. Ставит ветку на вершину другой ветки — на E.
4. Повторяет отложенные коммиты по одному, от старого к новому, — как будто ты начал работу
   только что:

    A---B---C---D---E          main
                     \
                      X'--Y'--Z'   search

## Как перенести

1. Встань в ветку, которую переносишь.
2. Назови `git rebase` ветку, на вершину которой её поставить:

    git rebase develop     # перенести текущую ветку на вершину develop

Изменения в коммитах те же, а хеши новые: это уже другие коммиты, сделанные «в другое
время». Поэтому переносят только свои ветки, которые ещё никто не забрал.
