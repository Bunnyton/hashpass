# Конфликт посреди переноса

`rebase` переносит коммиты по одному. На одном из них git упёрся: этот коммит и main
поменяли одно и то же место в файле, и git не знает, какая правка важнее. Перенос встал
на паузу и ждёт тебя — остальные коммиты ещё не перенесены.

Разрешается так же, как конфликт при слиянии: в файле между `<<<<<<<` и `>>>>>>>` обе
версии, оставь правильный итог и убери метки. Потом `git add` этого файла — так ты
говоришь git «здесь я разобрался».

А дальше не коммит, а продолжение переноса — у `git rebase` для этого есть ключ, его
называет сам git в своём сообщении. Git откроет редактор с сообщением коммита:
сохрани его и выйди, и перенос пойдёт дальше.

Запутался — у того же `git rebase` есть ключ, который отменяет перенос целиком и
возвращает ветку как было.
