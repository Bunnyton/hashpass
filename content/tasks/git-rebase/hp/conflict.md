# Конфликт посреди переноса

`rebase` переносит коммиты по одному. На одном из них git упёрся: этот коммит и main
поменяли одно и то же место в файле, и git не знает, какая правка важнее. Перенос встал
на паузу и ждёт тебя — остальные коммиты ещё не перенесены.

Как продолжить:

1. Открой файл с конфликтом — git назвал его в своём сообщении.
2. Между `<<<<<<<` и `>>>>>>>` лежат обе версии. Оставь правильный итог и убери метки —
   так же, как при конфликте слияния.
3. Сделай `git add` этого файла — так ты говоришь git «здесь я разобрался».
4. Дальше не коммит, а продолжение переноса: у `git rebase` для этого есть ключ, его
   называет сам git в своём сообщении.
5. git откроет редактор с сообщением коммита: сохрани его и выйди.
6. Перенос пойдёт дальше, к следующим коммитам. Встретится новый конфликт — снова шаги 1–5.

Запутался — у того же `git rebase` есть ключ, который отменяет перенос целиком и
возвращает ветку как было.
