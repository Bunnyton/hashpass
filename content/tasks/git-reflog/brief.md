# Журнал git

Вчера вечером ты хотел убрать из рукописи одну неудачную главу — и набрал `git reset --hard`
не на один коммит назад, а на три. А потом, «наводя порядок», удалил ветку `epilogue`. Сегодня
`git log` показывает четыре главы вместо семи, а `git branch` — одну ветку. Паника.

Зря. git почти ничего не удаляет сразу. Коммит, на который больше не указывает ни одна ветка,
ещё несколько недель лежит в репозитории — просто его не видно в `git log`.

## Журнал HEAD

А видно его в **журнале** — `git reflog`. Туда git записывает каждое перемещение HEAD:
коммит, переключение ветки, reset, rebase. Свежие записи сверху:

    a1b2c3d HEAD@{0}: reset: moving to HEAD~2
    f4e5d6c HEAD@{1}: commit: Добавил главу про кота
    0a9b8c7 HEAD@{2}: checkout: moving from draft to main

Как им пользоваться:

1. Открой журнал: `git reflog`.
2. Читай строку слева направо: хеш — где ты был, `HEAD@{N}` — сколько шагов назад, после
   двоеточия — что ты сделал.
3. Найди точку до ошибки — запись, где всё ещё было на месте.
4. Вернись на неё теми же командами, что и на любой коммит: хеш из журнала — такой же хеш.
