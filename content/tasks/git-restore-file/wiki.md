# Достать файл из прошлого

Удалённый полгода назад скрипт, конфиг, каким он был до неудачной правки, цены из релиза —
всё это лежит в истории git. Нужно найти коммит и достать из него один файл, не трогая
остальной проект.

## 1. Найти коммиты, где менялся файл

    $ git log --oneline -- backup.sh
    d98c8ee Уборка: старые скрипты
    61528fe backup.sh: комментарий
    eca3dd2 backup.sh: храним 14 копий
    61331ed backup.sh: без .git
    6f7c8c8 Скрипты: резервная копия и выкладка

`--` отделяет путь от имён коммитов: так git ищет даже файл, которого сейчас нет. Сверху —
последний коммит, тронувший файл. Здесь это удаление.

## 2. Взять версию до удаления

В коммите удаления файла уже нет:

    $ git show d98c8ee:backup.sh
    fatal: path 'backup.sh' does not exist in 'd98c8ee'

Нужен коммит на шаг раньше. Тильда работает с любым коммитом: `d98c8ee~1`.

    git show d98c8ee~1:backup.sh           # посмотреть
    git restore --source=d98c8ee~1 backup.sh   # вернуть файл на место

## 3. Файл из релиза

Тег — постоянное имя коммита. Вернуть один файл к релизу:

    $ git diff v1.0 -- prices.txt
    -пельмени-говядина  390
    +пельмени-говядина  3900
    $ git restore --source=v1.0 prices.txt

## Не откатывай весь проект

`git checkout v1.0` переключит **весь** рабочий каталог на релиз — HEAD отцепится от
ветки (detached HEAD), а все новые файлы пропадут из вида. Для одного файла это лишнее:
`restore --source` трогает только то, что назвал. Вернуться: `git switch main`.

## Шпаргалка

| Задача | Команда |
|---|---|
| история одного файла | `git log --oneline -- путь` |
| история с правками | `git log -p -- путь` |
| файл в коммите | `git show коммит:путь` |
| вернуть файл из коммита | `git restore --source=коммит путь` |
| старый способ | `git checkout коммит -- путь` |
| найти, где удалили | `git log --diff-filter=D --oneline -- путь` |
