# Причесать историю

Пока пишешь, коммитишь как получится: «wip», «опечатка», «ещё правка». Это нормально —
коммит дешёвый, им удобно сохраняться. Но в общую историю такая лесенка не нужна: через
полгода никто не поймёт, что было в «wip 2». Поэтому перед тем, как отдать ветку, её
**причёсывают**: складывают черновые коммиты в один осмысленный.

## Интерактивный rebase

Это тоже `git rebase` — только **интерактивный**, с ключом `-i`. Работает он так:

1. Запускаешь его и называешь ветку, поверх которой сделаны твои коммиты:

    git rebase -i develop     # переписать коммиты текущей ветки, сделанные поверх develop

2. git открывает в редакторе список этих коммитов, по одному в строке, сверху самый старый:

    pick 1a2b3c4 wip
    pick 5d6e7f8 исправил

3. Слово в начале строки — что сделать с этим коммитом. `pick` — оставить как есть. Какие
   ещё бывают слова, git пишет прямо в этом файле, ниже списка.
4. Меняешь слова там, где нужно, сохраняешь файл и выходишь из редактора.
5. git выполняет список сверху вниз.

Передумал — удали все строки списка и сохрани: переписывание отменится.
