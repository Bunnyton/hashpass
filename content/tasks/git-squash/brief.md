# Причесать историю

Пока пишешь, коммитишь как получится: «wip», «опечатка», «ещё правка». Это нормально —
коммит дешёвый, им удобно сохраняться. Но в общую историю такая лесенка не нужна: через
полгода никто не поймёт, что было в «wip 2». Поэтому перед тем, как отдать ветку, её
**причёсывают**: складывают черновые коммиты в один осмысленный.

Это тоже `git rebase` — только **интерактивный**, с ключом `-i`. Он открывает в редакторе
список коммитов ветки, по одному в строке, сверху самый старый:

    pick 1a2b3c4 wip
    pick 5d6e7f8 исправил

Слово в начале строки — что сделать с этим коммитом. `pick` — оставить как есть. Какие ещё
бывают слова, git пишет прямо в этом файле, ниже списка.

    git rebase -i develop     # переписать коммиты текущей ветки, сделанные поверх develop

Сохранил и вышел — git выполняет список сверху вниз. Удалишь все строки — переписывание
отменится.
