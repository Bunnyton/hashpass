# Полка git: отложить работу — git stash

Ты полдня делаешь новую фичу: правки в нескольких файлах, ничего не закоммичено и не работает
до конца. И тут срочный баг. Что делать с недоделкой?

- закоммитить полуготовое — в истории окажется сломанная версия;
- выкинуть — жалко;
- чинить поверх — в коммит с исправлением уедет и недоделка.

Для этого у git есть **полка** — `git stash`. Она забирает незакоммиченные изменения, хранит
их в репозитории, а каталог возвращает к последнему коммиту, будто ты ничего не трогал.

## Положить на полку

Пример: список покупок, в нём новая строка, плюс новый файл с идеями.

    $ git status -s
     M list.txt
    ?? ideas.txt
    $ git stash
    Saved working directory and index state WIP on main: 0b1cbef Начало
    $ git status -s
    ?? ideas.txt

`list.txt` уехал на полку, а `ideas.txt` — остался. Это главная ловушка полки.

## Новые файлы сами на полку не едут

Простой `git stash` забирает только то, за чем git **уже следит**: правки в файлах, которые
есть в истории, и то, что лежит в индексе. Новый файл (`??`, Untracked) git не знает и
оставляет в каталоге — вдруг это мусор, которому в истории не место.

Чтобы новый файл уехал вместе с остальным, два пути:

1. сначала `git add` его — тогда git о нём знает;
2. попросить `git stash` прихватить неотслеживаемые файлы — для этого у него есть ключ, ищи
   в `git stash --help` слово *untracked*. Есть и ключ «вообще всё, даже игнорируемое».

Проверка, что откладывать больше нечего, — `git status`: в нём не должно остаться ни строчки
об изменениях.

## Что лежит на полке

    $ git stash list
    stash@{0}: WIP on main: 0b1cbef Начало
    $ git stash show -p
    diff --git a/list.txt b/list.txt
    index fb87c0e..debf7b0 100644
    --- a/list.txt
    +++ b/list.txt
    @@ -1,2 +1,3 @@
     Покупки
     хлеб
    +молоко

Полок может быть сколько угодно: свежая — `stash@{0}`, предыдущие сдвигаются вниз
(`stash@{1}`, …). Чтобы через неделю понять, что где, подпиши: `git stash push -m "покупки"`.
Отложить только часть файлов — назови их: `git stash push -m "…" файл1 файл2`.

## Вернуть с полки: apply, drop, pop

Пока каталог чистый, можно спокойно починить баг и закоммитить исправление — в нём будет
только оно. Потом достаём отложенное:

    $ git stash apply
    On branch main
    Changes not staged for commit:
      (use "git add <file>..." to update what will be committed)
      (use "git restore <file>..." to discard changes in working directory)
    	modified:   list.txt
    …
    $ git stash list
    stash@{0}: WIP on main: 0b1cbef Начало

`apply` достаёт изменения, но **оставляет полку** — пригодится, если одну недоделку надо
положить в две ветки. Убрать полку — `drop`:

    $ git stash drop
    Dropped refs/stash@{0} (048c9bab70f9ec0881645534285635e1bc577fdb)
    $ git stash list

`git stash pop` — то и другое сразу: достать верхнюю полку и выбросить её (как снять тарелку
со стопки). Если при этом вышел конфликт, полка остаётся — на всякий случай.

Полки не привязаны к ветке: отложил в `main`, переключился в другую ветку — `git stash list`
там тот же, достать можно где угодно.

## Грабли

- **Достаёшь поверх своих правок** в тех же файлах — git откажет:

      error: Your local changes to the following files would be overwritten by merge:
      	list.txt
      Please commit your changes or stash them before you merge.
      Aborting

  Сначала закоммить или отложи текущее, потом доставай.
- **Полка — не архив.** Через месяц уже не вспомнишь, что в `stash@{3}`. Долгую работу
  храни в [ветке](/web/wiki/bunnyton/git-branch) с коммитами.
- `git stash clear` выбрасывает все полки разом, без вопросов.
