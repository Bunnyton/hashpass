# Тег на сервере не перезаписывается

Ветки ползут вперёд — это нормально. А тег обещает: «версия 1.9 — **вот этот** коммит,
навсегда». Поэтому сервер не даёт тихо поменять уже отправленный тег:

     ! [rejected]        v1.9 -> v1.9 (already exists)

Если тег действительно поставили не туда, его перезаписывают **осознанно** — с ключом
`--force`, как ветку после перестройки:

    git push --force origin v3.1

У тех, кто уже скачал старый тег, он сам не обновится: `git fetch` не трогает теги, которые
уже есть. Им нужно `git fetch --tags --force` — поэтому о переезде тега пишут команде.
