# Найти строку и сохранить в файл

Две привычки, на которых держится половина работы в терминале: **найти** нужные строки
(`grep`) и **сохранить** результат в файл (`>`), чтобы не потерять его вместе с экраном.

## grep — строки со словом

`grep слово файл` печатает только те строки файла, где встретилось слово:

    $ cat todo.md
    Список дел на неделю
    FIXME: поправить опечатку в шапке
    купить кофе
    fixme: проверить бэкап
    FIXME: обновить сертификат
    позвонить в банк
    $ grep FIXME todo.md
    FIXME: поправить опечатку в шапке
    FIXME: обновить сертификат

Регистр важен: `fixme` строчными не нашлось. Не важен — добавь `-i`. Номера строк — `-n`,
строки **без** слова — `-v`. Подробнее о ключах — в [wiki grep-hunt](/web/wiki/bunnyton/grep-hunt).

## `>` — вывод в файл

Всё, что команда печатает на экран, значок `>` отправляет в файл. Файла нет — он создастся;
есть — перезапишется с чистого листа:

    $ ls shop > list.txt
    $ cat list.txt
    cart.php
    index.html
    logo.png
    style.css

На экран при этом ничего не выходит — проверяй через `cat`.

Чтобы **дописать** в конец, а не затереть, есть `>>`:

    $ echo первая >> notes.txt
    $ echo вторая >> notes.txt
    $ cat notes.txt
    первая
    вторая

## Грабли

- `>` молча стирает старое содержимое. Опечатался в имени — потерял файл. Защита:
  `set -o noclobber`, тогда bash откажется перезаписывать существующий файл:

      $ set -o noclobber; echo x > notes.txt
      bash: line 1: notes.txt: cannot overwrite existing file

- Ошибки в файл через `>` не попадают — у них свой поток. Об этом задание
  [streams](/web/wiki/bunnyton/streams).
- Не направляй вывод в тот же файл, который команда читает: `>` очистит его ещё до того, как
  команда начнёт читать.

## Где пригодится

Сохранить список найденного, чтобы отправить коллеге; собрать отчёт из нескольких команд
(`>` для первой, `>>` для остальных); положить результат поиска рядом и работать с ним дальше.
