# Вывод в файл: > и >>

То, что команда напечатала на экран, исчезнет, как только экран прокрутится. А к письму, заявке
или отчёту экран не приложишь. Bash умеет отправить вывод любой команды **в файл** — одним
значком, без копирования мышью и без опечаток.

## `>` — в файл с чистого листа

    $ ls shop > list.txt
    $ cat list.txt
    cart.php
    index.html
    logo.png
    style.css

Что произошло:

- на экран `ls` ничего не вывел — всё ушло в `list.txt`;
- файла не было — bash создал его сам;
- заметь: в файле имена идут **по одному на строку**, хотя на экране `ls` выстраивает их в
  колонки. Когда вывод идёт не в терминал, `ls` печатает столбиком (как `ls -1`).

Если файл уже есть, `>` **стирает** его и пишет заново:

    $ date -d 2026-11-04 +%F > log.txt
    $ date -d 2026-11-05 +%F > log.txt
    $ cat log.txt
    2026-11-05

Первой даты больше нет. Голый `> файл` без команды просто создаёт пустой файл или очищает
существующий:

    $ > empty.txt; wc -c empty.txt
    0 empty.txt

## `>>` — дописать в конец

Старший брат `>`: файл не стирается, новые строки встают в конец.

    $ echo первая >> notes.txt
    $ echo вторая >> notes.txt
    $ cat notes.txt
    первая
    вторая

Так собирают отчёт из нескольких команд: первая — через `>`, чтобы начать с чистого файла,
остальные — через `>>`:

    $ echo "Отчёт от $(date -d 2026-11-04 +%F)" > report.txt; uname -r >> report.txt; cat report.txt
    Отчёт от 2026-11-04
    6.12.105+deb13-amd64

И так же, строка за строкой, растут журналы любой системы: каждая служба дописывает в свой
лог-файл, ничего не стирая.

## Ошибки идут мимо

`>` забирает только обычный вывод. Сообщение об ошибке всё равно появится на экране, а файл
останется пустым:

    $ ls nosuch > out.txt
    ls: cannot access 'nosuch': No such file or directory
    $ cat out.txt

У ошибок свой поток и своё перенаправление — это задание
[streams](/web/wiki/bunnyton/streams).

## Страховка от затирания

Перепутал `>` и `>>` — и файл потерян. Если боишься, включи `noclobber`: bash откажется
перезаписывать существующий файл через `>`:

    $ set -o noclobber; echo x > notes.txt
    bash: line 1: notes.txt: cannot overwrite existing file

Перезаписать всё-таки можно явно — `>|`. Выключить страховку — `set +o noclobber`.

## Где пригодится

- приложить к заявке или письму список файлов, версию программы, вывод диагностики;
- сохранить результат долгой команды, чтобы потом спокойно его разглядывать;
- вести свой журнал: `echo "$(date) — бэкап сделан" >> ~/backup.log`.

Дальше вывод можно отдавать не только в файл, но и другой команде — это конвейер `|`,
задание [pipes](/web/wiki/bunnyton/pipes).
