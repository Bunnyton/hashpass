# Своя команда: скрипт, PATH и где хранить данные

`ls`, `grep`, `cat` — не магия, а обычные файлы на диске. Значит, свою команду можно написать
самому: положить файл с командами в нужный каталог и разрешить его запускать.

## Как оболочка находит команду

Набираешь `ls` — bash перебирает каталоги из переменной **`PATH`** (через двоеточие) и
запускает первый найденный файл с таким именем:

    $ echo $PATH
    /usr/local/bin:/usr/bin:/bin
    $ which ls
    /usr/bin/ls
    $ type cd
    cd is a shell builtin

`cd` — исключение: он встроен в сам bash, файла у него нет. Файла нет в `PATH` — команды нет:

    $ hello
    bash: line 1: hello: command not found

Куда класть свои команды: `/usr/local/bin` — для всех пользователей (нужен `sudo`), `~/bin`
или `~/.local/bin` — только для себя (в Debian их добавляет в `PATH` `~/.profile`, если
каталог существует при входе). `/usr/bin` не трогай — там хозяйничает пакетный менеджер.

## Скрипт: шебанг и право на запуск

Первая строка `#!` (шебанг) говорит, какой программой выполнять файл:

    $ cat bin/hello
    #!/bin/bash
    echo "Привет, $USER! Сегодня $(date -d 2026-11-04 +%A)."

Без права `x` файл не запустится, даже если всё остальное верно:

    $ bin/hello
    bash: line 1: bin/hello: Permission denied
    $ chmod +x bin/hello; bin/hello
    Привет, anya! Сегодня Wednesday.

А когда каталог в `PATH`, путь писать не нужно — это уже команда:

    $ PATH=$PWD/bin:$PATH; hello; which hello
    Привет, anya! Сегодня Wednesday.
    /tmp/tmp.vXz5mwuWmy/bin/hello

`#!/bin/sh` — проще и быстрее, `#!/bin/bash` — со всеми удобствами bash. Для маленьких
скриптов подойдут оба.

## Переменные и арифметика

    $ n=5; echo $n
    5
    $ n = 5
    bash: line 1: n: command not found

Пробелов вокруг `=` быть не должно: иначе bash решит, что `n` — команда.

Считать — в `$(( ))`, только целые числа:

    $ a=2; b=3; echo $((a * b + 1))
    7
    $ echo $((7 / 2)) $((7 % 2)) $((2 ** 10))
    3 1 1024

Вывод команды — в переменную через `$( )`:

    $ echo 42 > num.txt; x=$(cat num.txt); echo $((x * 2))
    84

Кавычки: в двойных переменные раскрываются, в одинарных — нет:

    $ echo 'одинарные: $HOME'; echo "двойные: $HOME"
    одинарные: $HOME
    двойные: /home/anya

## Программа, которая помнит

Переменные живут, пока работает скрипт. Чтобы помнить между запусками, состояние кладут в
**файл**: прочитать в начале, записать в конце. Если файла ещё нет — `cat` ругнётся, поэтому
ошибку прячут и подставляют значение по умолчанию через `||` («если не вышло — то»):

    $ cat nofile
    cat: nofile: No such file or directory
    $ cat nofile 2>/dev/null || echo 0
    0

Пример — «гостевая книга», которая помнит последнего гостя:

    $ cat bin/guest
    #!/bin/bash
    prev=$(cat ~/.guest 2>/dev/null || echo "никого")
    echo "До тебя заходил: $prev"
    echo "$1" > ~/.guest
    $ guest Аня
    До тебя заходил: никого
    $ guest Боря
    До тебя заходил: Аня
    $ guest Вика
    До тебя заходил: Боря

Файлы с точкой в начале (`~/.guest`) — скрытые: `ls` их не показывает, `ls -a` — да. Так
программы прячут свои настройки и данные в домашнем каталоге.

## Что переживает перезагрузку

Где хранить — первый вопрос любой программы с памятью:

| Где | Живёт |
|---|---|
| `/tmp` | до перезагрузки: система очищает его при старте (часто это вообще память, `tmpfs`) |
| `/var/tmp` | переживает перезагрузку, но старое со временем чистят |
| `~` (домашний каталог) | пока не удалишь сам |

`/tmp` — для временного: черновики, блокировки, «уже запускался с момента включения». Домашний
каталог — для того, что должно помнить всегда.
