# Машины в сети: ping, curl, ssh

До сих пор была одна машина — та, в которой ты сидишь. В настоящей работе их много: твой
ноутбук, сервер с сайтом, база данных, принтер. Они соединены сетью, как компьютеры в одном
офисе. Здесь — как найти соседа, поговорить с его сайтом и зайти на него, чтобы что-то
поправить.

## Адреса и имена

У каждой машины в сети есть **адрес** IPv4 — четыре числа от 0 до 255 через точку:
`192.168.1.7`. Запись `10.20.0.10/24` значит «адрес 10.20.0.10 в сети, где первые три числа
общие» — все `10.20.0.*` соседи и видят друг друга напрямую. Свои адреса показывает
`ip -br addr`. Особый адрес `127.0.0.1` (имя `localhost`) — это всегда ты сам.

Помнить числа неудобно, поэтому у машин есть **имена**. Как имя превращается в адрес:

1. Сначала система смотрит файл `/etc/hosts` — таблицу «адрес имя»:

   ```
   127.0.0.1    localhost
   10.0.5.12    printer
   10.0.5.30    db  db.office
   ```

2. Не нашла — спрашивает **DNS**, «телефонную книгу» сети. Для маленькой сети хватает
   `/etc/hosts`, для интернета без DNS не обойтись.

Какой адрес система нашла для имени, скажет `getent hosts имя`.

## ping: ты тут?

`ping` посылает машине короткие сообщения и ждёт ответ. `-c 3` — три сообщения и стоп; без
него `ping` работает, пока не нажмёшь Ctrl+C.

    $ ping -c 3 127.0.0.1
    PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
    64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.043 ms
    64 bytes from 127.0.0.1: icmp_seq=2 ttl=64 time=0.045 ms
    64 bytes from 127.0.0.1: icmp_seq=3 ttl=64 time=0.053 ms

    --- 127.0.0.1 ping statistics ---
    3 packets transmitted, 3 received, 0% packet loss, time 2052ms
    rtt min/avg/max/mdev = 0.043/0.047/0.053/0.004 ms

`time` — сколько миллисекунд шёл ответ туда и обратно, в конце — итог. Две разные беды
выглядят по-разному. Имя неизвестно — до сети дело даже не дошло:

    $ ping -c 2 printer
    ping: printer: Name or service not known

Имя (или адрес) есть, но никто не отвечает — машина выключена, не в той сети или молчит
нарочно:

    $ ping -c 2 -W 1 10.255.255.1
    PING 10.255.255.1 (10.255.255.1) 56(84) bytes of data.

    --- 10.255.255.1 ping statistics ---
    2 packets transmitted, 0 received, 100% packet loss, time 1011ms

## curl: сайт без браузера

Сайт — это программа на другой машине (**веб-сервер**), которая по запросу отдаёт
страницу. Браузер только просит и рисует. Попросить можно и из консоли — `curl` печатает
ответ сервера как есть:

    $ curl http://127.0.0.1:18766/
    <!doctype html>
    <html><body>
    <h1>Склад открыт</h1>
    </body></html>

Адрес: `http://`, имя или адрес машины, `:порт` (без него — 80), путь. Пришёл **HTML** —
текст страницы с разметкой в угловых скобках, читать можно и глазами. Заголовки ответа
покажет `-I`:

    $ curl -I http://127.0.0.1:18766/
    HTTP/1.0 200 OK
    Server: SimpleHTTP/0.6 Python/3.13.5
    Content-type: text/html
    Content-Length: 77

`200 OK` — страница нашлась; `404` — такой нет; `500` — сервер сломался. Если имя не
находится, `curl` скажет об этом прямо:

    $ curl http://nosuchhost/
    curl: (6) Could not resolve host: nosuchhost

Полезные ключи: `-s` — без полоски прогресса, `-L` — идти по перенаправлениям, `-o файл` —
сохранить в файл.

## ssh: оказаться там

Файлы сайта лежат на сервере, а не у тебя: чтобы их поправить, нужно оказаться **там**.
`ssh пользователь@машина` открывает оболочку на другой машине:

1. В первый раз ssh покажет отпечаток ключа машины и спросит, доверяешь ли ты ей. Ответ
   `yes` — и ssh запомнит её в `~/.ssh/known_hosts`. Если потом отпечаток вдруг поменяется,
   ssh громко предупредит: возможно, тебя подменили.
2. Потом спросит пароль того пользователя **на той машине**.
3. Дальше всё, что набираешь, выполняется на сервере: те же `cat`, редактор, `sudo`. Где ты,
   видно в приглашении, а точно скажет `hostname`.
4. `exit` (или Ctrl+D) закрывает ssh и возвращает домой.

Одну команду можно выполнить и без входа: `ssh anna@printer uptime`. Пароль каждый раз
надоедает — вместо него ставят ключи (`ssh-keygen`, `ssh-copy-id`).

## Где веб-сервер берёт страницы

Веб-сервер отдаёт файлы из каталога, который записан в его настройках. У **nginx** настройки
сайтов в Debian лежат в `/etc/nginx/sites-enabled/`, а каталог страниц задаёт строка `root`:

```
server {
    listen 80;
    root /srv/site;          # отсюда отдаются файлы
    index index.html;        # что отдать на запрос «/»
}
```

Файлы сайта обычно принадлежат не тебе, а root или служебному пользователю — правят их через
`sudo` ([про sudo](/web/wiki/bunnyton/sudo-basics)). Статическую страницу nginx перечитывает
сам: поправил файл — следующий запрос уже получит новую версию. А вот правку **настроек**
nginx применяют `sudo systemctl reload nginx`.

## Свой мини-сайт за минуту

Хочешь поэкспериментировать — Python поднимет веб-сервер из любого каталога:

    python3 -m http.server 8000 --bind 127.0.0.1 -d каталог

Открывай `curl http://127.0.0.1:8000/`, Ctrl+C — остановить.
