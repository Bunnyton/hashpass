# Конвейер: |

Каждая команда в Linux делает одну вещь, но хорошо. Сила — в том, что их можно соединять:
вывод одной сразу становится входом другой. Соединяет их вертикальная черта `|` — **конвейер**
(по-английски pipe, «труба»).

## Как это работает

    команда1 | команда2

Вывод `команда1` не идёт на экран — он уходит на вход `команда2`. Та обрабатывает его так же,
как обработала бы файл. На экран выходит только то, что напечатало **последнее** звено.

Пример — журнал небольшого магазина:

    $ cat shop.log
    2026-11-01 10:00:01 INFO  api-1 nginx: request ok
    2026-11-01 10:00:02 WARN  api-2 redis: slow reply
    2026-11-01 10:00:03 ERROR api-1 redis: connection refused
    2026-11-01 10:00:04 ERROR db-1 mysql: disk full
    2026-11-01 10:00:05 ERROR api-2 redis: timeout
    2026-11-01 10:00:06 INFO  db-1 mysql: backup done

Один `grep` ищет одно слово. А если условий два — «предупреждения от redis»? Фильтруем
отфильтрованное:

    $ grep redis shop.log | grep WARN
    2026-11-01 10:00:02 WARN  api-2 redis: slow reply

Первый `grep` оставил строки с `redis`, второй из них — только с `WARN`. Порядок фильтров
здесь не важен, результат тот же.

## Звеньев — сколько угодно

Фильтры можно чередовать с другими командами. Вот «сколько ошибок у каждой службы»:

    $ grep ERROR shop.log | awk '{print $5}' | sort | uniq -c
          1 mysql:
          2 redis:

Четыре звена: найти ошибки → взять пятый столбец → отсортировать → посчитать повторы. Про
`sort`/`uniq` — [wiki fruit-store](/web/wiki/bunnyton/fruit-store), про столбцы и `awk` —
[wiki xargs](/web/wiki/bunnyton/xargs).

Совет: собирай конвейер **по звену**. Добавил звено — посмотрел на экран — добавил следующее.
Ошибка сразу видна на том шаге, где появилась.

## Минус слово: `grep -v`

Иногда проще сказать, чего **не** надо:

    $ grep ERROR shop.log | grep -v redis
    2026-11-01 10:00:04 ERROR db-1 mysql: disk full

## Конвейер и файл

`>` в конце сохраняет то, что вышло из последнего звена:

    $ grep ERROR shop.log | grep mysql > mysql-errors.txt; cat mysql-errors.txt
    2026-11-01 10:00:04 ERROR db-1 mysql: disk full

Тот же результат можно получить и через временный файл — но конвейер не оставляет мусора и
работает, пока данные ещё текут: первое звено не ждёт конца файла, второе уже читает.

Хочешь и сохранить, и пустить дальше — `tee` пишет копию в файл и передаёт поток следующему
звену:

    $ grep ERROR shop.log | tee errors.txt | wc -l
    3

## Грабли

- Слово попадается не только там, где ждёшь: `grep web` найдёт и `web-1`, и `webhook`, и
  `cobweb`. Смотри на результат глазами, уточняй шаблон (`-w` — целое слово).
- `|` передаёт только обычный вывод, ошибки идут мимо, на экран. Подробнее —
  [wiki streams](/web/wiki/bunnyton/streams).
- `cat файл | grep слово` работает, но `grep слово файл` короче: `cat` в начале конвейера
  обычно лишний.
