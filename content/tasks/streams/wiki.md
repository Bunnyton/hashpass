# Потоки: stdin, stdout, stderr

У каждой программы три «трубы»: в одну она читает, в две другие пишет. Обычный вывод и
сообщения об ошибках — **разные** потоки, и поэтому их можно сохранять, читать и выбрасывать
по отдельности.

| Номер | Имя | Что это | По умолчанию |
|---|---|---|---|
| 0 | stdin | ввод | клавиатура |
| 1 | stdout | обычный вывод | экран |
| 2 | stderr | ошибки и служебные сообщения | экран |

Примеры ниже — на скрипте, который пишет по строке в каждый поток:

    #!/bin/bash
    echo "это stdout"
    echo "это stderr" >&2

## Запуск своего скрипта

Программу из текущего каталога запускают по пути — `./имя`. Без права на запуск bash откажет:

    $ ./talk.sh
    bash: line 1: ./talk.sh: Permission denied
    $ chmod +x talk.sh; ls -l talk.sh
    -rwxrwxr-x 1 anya anya 58 Nov  4 02:17 talk.sh

`x` в правах — разрешено исполнять.

## `>` забирает только stdout

    $ ./talk.sh > out.log
    это stderr
    $ cat out.log
    это stdout

Ошибка осталась на экране: `>` — это сокращение от `1>`, он трогает только поток 1. Так задумано:
даже если вывод ушёл в файл, ты всё равно увидишь, что что-то сломалось.

## Номер перед `>` — любой поток

    $ ./talk.sh 2> err.log
    это stdout
    $ cat err.log
    это stderr

В одной команде можно перенаправить оба потока, каждый в свой файл — просто напиши оба
перенаправления подряд. `>>` с номером тоже работает: `2>> err.log` дописывает ошибки в конец.

## `/dev/null` — чёрная дыра

`/dev/null` — особый файл: всё, что в него пишут, исчезает, а читать из него — пусто.

    $ ls /etc/passwd /nosuch
    ls: cannot access '/nosuch': No such file or directory
    /etc/passwd
    $ ls /etc/passwd /nosuch 2>/dev/null
    /etc/passwd

Так прячут ожидаемые ошибки: `find / -name x 2>/dev/null` без сотен «Permission denied».

## Поток в поток: `2>&1`

`2>&1` значит «stderr — туда же, куда **сейчас** идёт stdout». Перенаправления читаются
**слева направо**, поэтому порядок решает:

    $ ./talk.sh > all.log 2>&1; cat all.log
    это stdout
    это stderr
    $ ./talk.sh 2>&1 > only.log
    это stderr

Во втором случае `2>&1` сработал, когда stdout ещё смотрел на экран, — туда stderr и ушёл, а
потом stdout переехал в файл один. У bash есть и короткая запись «оба потока в файл»: `&> файл`.

Конвейер `|` тоже передаёт только stdout. Чтобы следующая команда увидела и ошибки, их
сливают заранее:

    $ ls /nosuch | wc -l
    ls: cannot access '/nosuch': No such file or directory
    0
    $ ls /nosuch 2>&1 | wc -l
    1

## `<` — файл на вход

`<` — зеркало `>`: он не забирает вывод, а **подаёт файл на stdin** команды, будто его
набрали с клавиатуры. Команда читает поток и не знает, как назывался файл:

    $ wc -l words.txt
    2 words.txt
    $ wc -l < words.txt
    2

Так получают «голое» число без имени файла — удобно, чтобы подставить его в скрипт.

## Шпаргалка

| Запись | Что делает |
|---|---|
| `> f` / `1> f` | stdout в файл (с чистого листа) |
| `>> f` | stdout в конец файла |
| `2> f` | stderr в файл |
| `2>&1` | stderr туда же, куда stdout сейчас |
| `&> f` | оба потока в файл (bash) |
| `< f` | файл на stdin |
| `/dev/null` | выбросить |
