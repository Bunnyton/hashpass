# top — диспетчер задач Linux

Компьютер тормозит, вентилятор воет. В Windows жмут Ctrl+Shift+Esc, в Linux набирают **`top`**:
живой список процессов, который сам обновляется каждые 3 секунды. Он есть на любом сервере —
даже там, где нет ни `htop`, ни мыши.

## Шапка: состояние системы целиком

Первые пять строк — сводка. Снимок `top -b -n1` (b — печатать текстом, n1 — один раз):

    $ top -b -n1 -o %CPU -p 396274,396275
    top - 02:18:27 up 1 day,  8:28,  1 user,  load average: 3.32, 2.77, 10.99
    Tasks:   2 total,   1 running,   1 sleeping,   0 stopped,   0 zombie
    %Cpu(s):  5.5 us,  5.9 sy,  6.4 ni, 81.7 id,  0.5 wa,  0.0 hi,  0.0 si,  0.0 st
    MiB Mem :  15507.3 total,    424.8 free,  11867.9 used,   6434.7 buff/cache
    MiB Swap:  19064.0 total,   8569.9 free,  10494.1 used.   3639.3 avail Mem

- **load average** — сколько процессов в среднем хотели процессор за 1, 5 и 15 минут. Больше,
  чем ядер (`nproc`), — система не успевает;
- **Tasks** — сколько процессов и в каких состояниях (`zombie` — про них
  [отдельное задание](/web/wiki/bunnyton/zombies));
- **%Cpu(s)** — куда уходит процессор: `us` — программы, `sy` — ядро, `id` — простой,
  `wa` — ожидание диска;
- **Mem** — память. Смотри на `avail Mem`, а не на `free`: под кэш (`buff/cache`) Linux
  забирает всё свободное и отдаёт обратно по первому требованию.

## Таблица процессов

Здесь запущены два подопытных: `spinner` крутит пустой цикл, `python3` держит 300 МБ памяти.

        PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
     396274 anya      25   5    5568   1924   1804 R 100.0   0.0   0:03.19 spinner
     396275 anya      25   5  324400 316572   6292 S   0.0   2.0   0:00.21 python3

    PID       номер процесса — по нему процесс останавливают
    USER      от чьего имени он работает
    PR, NI    приоритет и «вежливость» (nice): чем больше NI, тем охотнее уступает
    VIRT      сколько памяти процесс «заказал» — часто сильно больше настоящей
    RES       сколько настоящей памяти он занимает сейчас, в КиБ
    S         состояние: R — работает, S — спит, T — остановлен, Z — зомби
    %CPU      доля процессора; 100 — одно ядро целиком, на 4 ядрах бывает и 400
    %MEM      RES в процентах от всей памяти
    TIME+     сколько процессорного времени он съел за всю жизнь
    COMMAND   имя программы

## Клавиши внутри top

    P          сортировать по %CPU (так top и открывается)
    M          сортировать по памяти (%MEM)
    k          послать сигнал: спросит PID (по умолчанию — верхний), потом сигнал (15 — TERM)
    c          показать полную командную строку вместо имени
    u          только процессы одного пользователя
    1          каждое ядро отдельной строкой
    q          выйти

Отсортировал по памяти — и наверху другой процесс:

    $ top -b -n1 -o %MEM -p 396274,396275 | tail -3
        PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
     396275 anya      25   5  324400 316572   6292 S   0.0   2.0   0:00.21 python3
     396274 anya      25   5    5568   1924   1804 R 100.0   0.0   0:03.40 spinner

Самый прожорливый по процессору и самый прожорливый по памяти — часто **разные** процессы.

## Остановить процесс

Из top — `k`, из командной строки — `kill` с номером:

    $ kill 396274
    $ ps -o pid,stat,comm -p 396274,396275
        PID STAT COMMAND
     396275 SN   python3

`kill` без ключей посылает вежливый сигнал TERM — «заверши работу». Подробно про сигналы —
в [задании signals](/web/wiki/bunnyton/signals). Свои процессы останавливать можно, чужие — только
через `sudo`.

## Где это пригодится

- сервер «тормозит» — первым делом `top`, `P`, смотришь, кто наверху;
- память кончается — `M`, кто держит больше всех в `RES`;
- снимок в отчёт или скрипт: `top -b -n1 | head -20`.

Красивее и удобнее — `htop` и `btop`: [их задание](/web/wiki/bunnyton/htop-btop).
