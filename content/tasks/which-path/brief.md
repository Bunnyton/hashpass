# Где лежит программа

Команда — это просто **исполняемый файл** в каком-то каталоге. `ls`, `cat`, `grep` — такие же
файлы, как твои скрипты, только их положил туда пакет:

    $ ls -l /usr/bin/cat
    -rwxr-xr-x 1 root root 47592 Jun  4  2025 /usr/bin/cat

Буквы `x` в правах — разрешение исполнять. В `/usr/bin` таких файлов сотни: загляни туда
`ls /usr/bin` — это почти все команды, которые ты знаешь. И любую можно запустить полным
путём, вообще без поиска: `/usr/bin/cat файл` — то же самое, что `cat файл`.

Откуда же оболочка знает, что `cat` — это `/usr/bin/cat`? Она ищет файл с таким именем
в каталогах из переменной `PATH`:

    $ echo $PATH
    /usr/local/bin:/usr/bin:/bin

Поэтому твоя команда в `/usr/local/bin` и заработала по имени: файл лежит в каталоге из
`PATH` и у него есть `x`. Убери любое из двух — и будет:

    $ hello                     # файл есть, но не в каталоге из PATH
    bash: hello: command not found
    $ ./hello                   # путь указан сам — поиск не нужен
    Привет
    $ /usr/local/bin/hello      # лежит в PATH, но без x
    bash: /usr/local/bin/hello: Permission denied

А почему именно `/usr/local/bin`, а не `/usr/bin`? `/usr/bin` принадлежит пакетам: `apt` там
хозяйничает и при обновлении перезапишет чужой файл, не спросив. `/usr/local` — для того,
что ставят руками, мимо пакетов, туда `apt` не лезет.

Оболочка ищет **слева направо** и запускает **первый** найденный файл. Остальные с тем же
именем она даже не видит — даже если они новее.

Спросить, что запустится, можно у самой оболочки:

    $ which python3
    /usr/bin/python3
    $ type ls
    ls is aliased to `ls --color=auto'

`type` честнее: он знает и про псевдонимы, и про встроенные команды оболочки (`cd` — не файл,
его не найти ни в одном каталоге: менять каталог самой оболочки может только она сама).
