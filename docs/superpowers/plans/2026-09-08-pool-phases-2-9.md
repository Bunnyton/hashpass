# Pool — phases 2-9 (consolidated plan)

**Spec:** `docs/superpowers/specs/2026-09-08-hashpass-hashengine-pool-design.md`. One commit per phase,
booted → ff main → push. Fast tests (tier1/tier2 loopback) each phase; real-server integration
(`root@135.106.177.228`) at milestones (after 4, after 6, after 7).

## Phase 2 — users, roles, registration
- `registry/passwords.py`: `UserStore` record → dict `{pw, role, full_name, group, comment, created_at}`;
  back-compat with legacy str records. Methods: `add(user, pw, *, role="student", full_name, group,
  comment)`, `has`, `verify`, `get(user)->profile`, `role(user)`, `set_role`, `all_users()`.
- `registry/config.py` (new): `ServerConfig` (`registration_open: bool=True`) persisted to `config.json`.
- `registry/server.py`: thread `config` into `RegistryServer`/`make_server`; add `POST /register`
  (toggle-gated, requires non-blank full_name+group, 409 on dup, returns a token), `GET /me` (bearer
  → {user,role,full_name,group}), `POST /admin/registration` (admin), `POST /admin/role` (admin).
  Add `_require_role`.
- `registry/remote.py`: `register(user, pw, full_name, group, comment)`, `me()`, `set_registration`,
  `set_role` client methods.
- `cli.py` `_require_login` local auto-create → role="admin" (machine owner).
- Tests: passwords (profile/role/legacy), server (register happy/closed/blank/dup, me, admin gating).

## Phase 3 — task transfer + digest
- `registry/blob.py`: `pack_task(task_dir)` / `unpack_task(blob, dest)` (tar of `task/{bundle,hp,task-meta.json}`).
- `taskdigest.py` (new, hashcore): `task_digest(task_dir)->str` = sha256 over sorted bundle+hp+meta.
- `registry/server.py`: `PUT /task/<name>/<ver>` (author role; stores task/ under the image dir;
  `?number=N` → catalog in phase 4), `GET /task/<name>/<ver>` (bearer → task blob).
- `registry/remote.py`: `push_task`, `pull_task`.
- Tests: digest determinism + mismatch; task pack/unpack round-trip; /task PUT auth + GET.

## Phase 4 — catalog + numbering
- `registry/catalog.py` (new): `Catalog` over `catalog.json` (`{number:{name,version,title,digest}}`);
  add/overwrite/list ordered.
- `registry/server.py`: `GET /catalog` (bearer → ordered list); `PUT /task?number=N&title=` writes catalog.
- `cli.py cmd_push` + `hashengine push --task N --title`: push image closure + task blob + catalog slot.
- `registry/remote.py`: `catalog()`.
- Tests: catalog add/overwrite/order; push --task N end-to-end (loopback).
- **Server milestone A:** deploy to 135.x, `hashengine serve`, push a task with a number, GET /catalog.

## Phase 5 — student client
- `cli.py`: `pool.json` read/write (URL + cached login); first-run gate (`_require_pool_identity`):
  no token → register/login prompt; `cmd_register`.
- Parallel pull: `pull_new(catalog, store)` — ThreadPool over `RemoteRegistry.pull` for new/changed refs.
- `student_cli`: no-arg → update-check(ph9) + parallel pull + list-by-number with pass status; `run <N|ref>`
  resolves number via catalog; real `student_id` = pool login (replace `_DEFAULT_STUDENT`).
- Tests: pool.json round-trip; parallel pull (mock remote, assert all fetched, concurrency); number→ref.

## Phase 6 — submit + progress
- `registry/progress.py` (new server-side): `ProgressStore` (`progress/<user>.json`), record passed/failed.
- `server.py`: `POST /submit` (bearer → verify evidence via `server/verify.py` + digest match →
  record + return {status, global_key?}; principal-bind student_id to the token user); `GET /progress`
  (author→all, student→self).
- `grade.py`/`taskrun.py`/`cli.py`: on a live pass, build evidence, compute local digest, POST /submit.
- `registry/remote.py`: `submit(evidence, digest)`, `progress()`.
- Tests: submit verify+digest-match→passed; digest-mismatch→failed+no key; principal mismatch→reject;
  progress persistence; author-sees-all vs student-self.
- **Server milestone B:** full flow on 135.x — register → (author push) → pull → run locally → submit → progress.

## Phase 7 — web UI
- `registry/web.py` (new): stdlib HTML views; wire into `_Handler` under `/web`, `/install.sh`,
  `/install-engine.sh`, front page `/`.
- Screens: login (author/admin, HMAC cookie), dashboard (students × task numbers, pass cells; filter by
  group), users (create/list, grant author, open/close registration), front page (install one-liner).
- Tests: login sets cookie; dashboard renders expected rows; registration-closed path; student blocked.
- **Server milestone C:** open the dashboard in a browser against 135.x; verify progress shows.

## Phase 8 — installer (pool-served) + two-distribution packaging
- `registry/web.py`: `/install.sh` templated with pool URL (writes pool.json, pip-installs `hashpass`
  from GitHub release); `/install-engine.sh` (author-gated). Dry-run env for tests; shellcheck.
- Packaging: relocate engine-only modules (build, image/base, taskbuild, registry/server+web+passwords+
  config+catalog+progress) into `hashengine`; two pyproject dists (`hashpass`, `hashengine` deps
  `hashpass`); `make install`(engine) / `make install-student`(hashpass only).
- Tests: install.sh shellcheck + dry-run asserts pip target + pool.json seed; import boundary (student
  dist has no engine modules).

## Phase 9 — auto-update
- `version.py` (hashcore): real `__version__`; `is_newer(a,b)` (dotted numeric); `check_and_update()`
  — GET GitHub releases/latest (mockable), stamp `update.json` (24h), on newer pip-install tag + re-exec;
  `--no-update`/`HASHPASS_NO_UPDATE`. Bump `pyproject` version; tag a release.
- Wire launch-time check into both `main`s.
- Tests: is_newer table; check triggers only on strictly-newer; network failure swallowed; re-exec mocked.
