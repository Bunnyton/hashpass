# 1а. Ревизии и теги образов — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.

**Goal:** каждый `push` создаёт неизменяемую ревизию `name:tag_vN`; `tag`, `rm`, `fork` и разрешение
`tag`/`tag_latest`/`tag_vN` работают на сервере и в клиенте; модерация каталога работает поверх
ревизий (одобренная версия = ревизия, `ApprovedStore` больше не нужен).

**Architecture:** ревизия — обычный каталог `ImageStore` с версией `<tag>_v<N>` (переиспользуем
хранилище, blob-ы, `closure_refs`). Индекс тегов — новый модуль `registry/revisions.py`
(`repos/<owner>/<name>/repo.json`, под `fcntl`-блокировкой). Отправка — черновик (отдельный
`ImageStore`/`AttachmentStore`/`SourceStore` в `.staging/<id>/`) и `commit`, который под
блокировкой репозитория присваивает N, закрепляет родителей и переносит каталоги черновика.
Одинаковое содержимое (хеши) → ничего не создаётся. `tag`/`fork` — новые ревизии с жёсткими
ссылками на те же blob-ы и копией `task/`.

**Tech Stack:** Python 3.13, Flask/werkzeug, pytest (tier1), ruff.

**Spec:** `docs/superpowers/specs/2026-10-21-курсы-и-рабочий-tui-design.md` §2 (2.1–2.4, 2.7, 2.8 —
только модель форка и `fork_of`; запросы на слияние — план 1в), §12.

## Global Constraints

- Суффиксы `_v<цифры>` и `_latest` в теге запрещены (`build`, `push`, `tag`, `fork`).
- Номера ревизий не переиспользуются (в `repo.json` хранится `next`).
- Ревизии неизменяемы; `push`/`commit` никогда не перезаписывает существующий `tag_vN`.
- Родители закрепляются на ревизиях при `commit`.
- Чужой namespace: запись запрещена (`_may_write`); чужой образ не перетегировать.
- Старый `hashengine push` (без черновика) получает понятный отказ 426: «обновите hashengine» (он
  обновляется сам при запуске). *Отклонение от спеки §2.3 («фиксирует PUT /task») согласовано как
  мелкое: старые клиенты самообновляются; фиксация по PUT /task давала бы полуревизии.*
- Тексты для людей — по-русски; код/коммиты — по-английски.
- Прод не трогаем.

## Review Focus

1. Две параллельные отправки в один тег → `_v2` и `_v3`, не два `_v2` (тест с потоками).
2. Отправка без изменений (тот же `image_digest` и `task_digest`) → 200 `{"unchanged": true}`, ревизия не создаётся.
3. Задание с родителем чужого namespace (`bunnyton/debian:trixie`) — родитель не отправляется, а закрепляется на последней ревизии на пуле; нет на пуле → 409 с понятной причиной.
4. Клиент скачивает `x:1` → получает `x:1_v3` и закреплённых родителей, хранит их под именами ревизий, запускает без сети.
5. Удаление ревизии, на которую ссылаются потомки через `from` → 409 со списком.

```python

def check_tag(tag: str) -> None    # ValueError «тег … оканчивается на зарезервированный суффикс»
def revision_version(tag: str, n: int) -> str          # "1", 3 -> "1_v3"
def parse_version(version: str) -> tuple[str, int | None, bool]
    # "1_v3" -> ("1", 3, False); "1_latest" -> ("1", None, True); "1" -> ("1", None, False)

@dataclass(frozen=True)
class Revision:
    n: int; image_digest: str; task_digest: str
    parents: tuple[str, ...]        # закреплённые refs "owner/name:tag_vN"
    at: str; by: str; merged_from: str = ""

class RepoIndex:                    # repos/<name>/repo.json (name может быть многосегментным)
    def __init__(self, root: Path, name: str) -> None
    @contextmanager
    def locked(self) -> Iterator["RepoIndex"]        # fcntl.flock на repos/<name>/.lock; перечитывает
    def tags(self) -> list[str]
    def revisions(self, tag: str) -> list[Revision]  # по возрастанию n

    def get(self, tag: str, n: int) -> Revision | None
    def add(self, tag: str, rev_without_n: dict) -> Revision   # только внутри locked(); n = next[tag]
    def remove(self, tag: str, n: int) -> None

    hide_sources: bool
    fork_of: str                    # "owner/name:tag_vN" или ""
    def set_meta(self, **fields) -> None             # только внутри locked()
```

### Task 3: Черновик и `commit` на сервере

**Files:**
- Create: `src/hashpass/registry/staging.py`
- Modify: `src/hashpass/registry/server.py` (маршруты, PUT-обработчики image/task/source/attachment)

**Interfaces — Produces (HTTP):**
- `POST /revisions/<name>/<tag>` (владелец namespace/админ) → `201 {"staging": "<hex32>"}`;
  тег с зарезервированным суффиксом → `400 {"error": …}`.
- `PUT /image/<name>/<tag>?staging=<id>` — blob в черновик (meta в blob: `name`, `version=<tag>`).
- `PUT /task/<name>/<tag>?staging=<id>[&publish=1&block=B]` — `task/` в черновик; флаги
  запоминаются в `staging/<id>/intent.json` и применяются при commit.
- `PUT /source/<name>/<tag>?staging=<id>`, `PUT /attachment/<name>/<tag>?staging=<id>&name=…`.
- `POST /revisions/<name>/<tag>/commit {"staging": id}` →
  `201 {"ref": "name:tag_vN", "n": N}` | `200 {"ref": "name:tag_vM", "n": M, "unchanged": true}` |
  `409 {"error": "родитель … не найден на пуле"}` | `400` (пустой черновик без образа и без
  предыдущей ревизии).
- PUT без `staging` на `/image|/task|/source|/attachment` → `426 {"error": "обновите hashengine:
  пул принимает отправку ревизиями (hashengine обновится сам при следующем запуске)"}`.

**`staging.py` Produces:**
```python
class Staging:
    def __init__(self, root: Path, sid: str) -> None    # root/.staging/<sid>/
    images: ImageStore; attachments: AttachmentStore; sources: SourceStore
    intent: dict                                         # {"owner", "name", "tag", "publish", "block", "created"}
    def save_intent(self) -> None
    def remove(self) -> None
def new_staging(root: Path, owner: str, name: str, tag: str) -> Staging
def sweep_stale(root: Path, max_age: float = 86400) -> None
```
**Commit algorithm (под `repo.locked()`):**
1. `latest = idx.latest(tag)`.
2. image: если в черновике есть `name:tag` — его digest; иначе — `latest.image_digest` (нет latest
   → 400 «нечего фиксировать»).
3. task: если в черновике есть `task/` — `task_digest(...)`; иначе — `latest.task_digest`.
4. Родители: `parents` из meta черновика (`name:tag`, как в blob) → каждый в закреплённую ревизию:
   уже ревизия (`_vN`) — как есть; иначе `_resolve` → последняя; не найдено → 409.
5. `latest` есть и `(image, task, parents)` совпадают → `200 unchanged`, черновик удалить.
6. `n = idx.add(...)`; версия `tag_vN`: образ из черновика — перенести каталог
   `staging.images.dir(name, tag)` → `store.dir(name, tag_vN)` (rename) и переписать meta
   (`version`, `parents`); образа в черновике нет — `store.link_revision(latest_ref, name, tag_vN, parents=…)`.
   `task/` черновика переносится поверх (если есть). Вложения и исходники: из черновика, а чего нет —
   копия из `latest`.
7. Каталог (`publish` в intent): `catalog().add_task("name:tag", task_digest, …, image=image_digest,
   block_name=…)` — запись каталога по-прежнему на тег (`name:tag`), см. Task 5.
8. Удалить черновик; `sweep_stale` по пути.
