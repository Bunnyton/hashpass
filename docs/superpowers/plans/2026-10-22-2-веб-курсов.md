# 2. Веб курсов — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.

**Goal:** веб-интерфейс курсов и образов по спеке §11: список курсов, страница курса (персоналу —
предложения, заявки, участники, студенты, настройки; всем — задания и «Пройти»/«Запросить доступ»),
карточка образа с ревизиями, видимостью, «где используется», «Предложить в курс», удалением,
форком и запросами на слияние; админу — поиск пользователей и запросы на удаление.

**Architecture:** страницы — серверные шаблоны Jinja (`registry/templates`), данные берутся из
тех же функций, что и JSON API. Действия — `fetch` в JSON API (`/courses…`, `/revisions…`,
`/deletion-requests…`, `/users/search`), который принимает и bearer-токен, и cookie-сессию веба
(`hp_session`). Один скрипт `static/api.js`: формы `data-api="METHOD /path"` отправляют поля как
JSON (`data-json-bool` для чекбоксов), при успехе — перезагрузка (`data-then="reload"`) или
переход (`data-then="go:/c/{ref}"`), при ошибке — тост с текстом `error`. Редактор порядка
(`catalog.js`) получает URL сохранения из `data-layout-url` и `rev` из `data-rev`.

**Spec:** `docs/superpowers/specs/2026-10-21-курсы-и-рабочий-tui-design.md` §11 (+ §2.5–§2.8, §4–§7).

## Global Constraints

- Все тексты — по-русски, в стиле существующих страниц (`style.css`, пилюли, меню «⋯»).
- Права — только серверные проверки API; шаблон лишь прячет недоступные кнопки.
- Курсовые страницы открыты всем вошедшим (публичный курс — и анонимно на просмотр); старые
  страницы `/web`, `/web/images` остаются для админа/авторов до переезда.
- Без новых внешних зависимостей (htmx уже подключён, но не обязателен).

## Tasks

### Task 1: Сессия в API, раскладка курса, поиск пользователей в API курсов
- `CourseApi._caller` и `PoolServer._token_user` для API: bearer, иначе cookie `hp_session`
  (`_session_user`). Тест: GET `/courses/<o>/<n>` с cookie видит приватный курс участника.
- `PUT /courses/<o>/<n>/layout {blocks: [{id, tasks: ["repo:tag"]}], rev}` (moderate): порядок
  блоков и заданий, перенос между блоками; неизвестные задания — 400; потерянные — 400.
- Тесты API.

### Task 2: `api.js` + список курсов `/c` и создание `/c/new`
- `render_courses(rows, q, signed_in)`; поиск `?q=`; форма создания (имя, название, видимость).
- Навигация: пункт «Курсы» (`/c`) для всех вошедших.
- Тесты рендера и маршрута.

### Task 3: Страница курса `/c/<o>/<n>`
- Шапка: название, владелец, видимость, описание, «Пройти» (ссылка курса + `hashpass add <ссылка>`;
  для приватного — с `?invite=` персоналу), кнопка «Вступить» (публичный) / «Запросить доступ».
- Посторонний приватного — только шапка и «Запросить доступ» / «заявка отправлена».
- Задания по блокам (`revision`, отметки «закреплено», «скрыто»); «Предложить задание» (repo, tag,
  комментарий) — всем, кто может; автор+ — «Добавить».
- Вкладки персонала: «Редактор» (блоки, перетаскивание, «⋯»: выше/ниже, скрыть/показать,
  закрепить/открепить, обновить до vN, убрать), «Предложения» (открытые + обновления: принять /
  отклонить с причиной; свои — отозвать), «Заявки», «Участники» (роль, убрать; ссылка-приглашение,
  «сменить»), «Студенты» (приступившие: прогресс по заданиям курса), «Настройки» (название,
  описание, видимость, автопринятие, автообновление, удалить курс).
- `?invite=<токен>` на странице: вошедший — кнопка «Вступить по приглашению».

### Task 4: Карточка образа
- Ревизии по тегам (n, когда, кто, `merged_from`, «последняя»), видимость и «скрыть служебные
  файлы» (владелец), «Где используется» (курсы; чужие приватные — «ещё N»), «Предложить в курс…»
  (курсы, где можно предлагать, блок, комментарий), «Удалить ревизию» (владелец: ответ 202 —
  «ждёт решения администратора»), «Форкнуть» (имя), «форк …» со ссылкой; у форка — «Предложить
  автору»; у исходного — «Запросы на слияние» с diff по файлам и «Принять/Отклонить».
- Карточка доступна любому вошедшему, кто видит репозиторий.

### Task 5: Пользователи и удаления (админ)
- `/web/users`: поле поиска (логин или комментарий) → `/users/search`; список запросов на удаление
  ревизий с «Одобрить/Отклонить».

### Task 6: Живая проверка
- Пул `:8091` с `HASHPASS_COURSES=1`, headless Chromium (CDP-драйвер из памяти
  `web-verify-headless-chromium`): создать курс, блок, добавить задание, перетащить, предложить от
  другого пользователя, принять, заявка → принять, приглашение, настройки; карточка: ревизии, форк,
  слияние с diff; скриншоты ключевых экранов.
