# Роли: админы с галочками — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** На пуле остаются пользователь и админ с четырьмя галочками прав; курс управляет собой через
владельца, админов (с галочками), авторов и участников.

**Architecture:** Новый модуль `registry/perms.py` хранит ключи галочек и значения по умолчанию.
`UserStore` и `Course` нормализуют старые записи при чтении. `access.can()` принимает права админа пула
(`frozenset`) вместо серверной роли. Каждая проверка на пуле, которая сейчас смотрит на роль, переходит
на `self._perm(user, key)`.

**Tech Stack:** Python 3.13, Flask, Jinja2, pytest (tier1/tier2), ruff.

**Spec:** `docs/superpowers/specs/2026-10-25-роли-админы-и-права-design.md`

## Global Constraints

- Галочки: `admins`, `content`, `people`, `progress`. По умолчанию у нового админа (пула и курса):
  `content`, `people`, `progress`.
- Владелец пула (`config.json` → `owner`; без поля — `$HASHPASS_ADMIN`, по умолчанию `admin`, если это
  админ, иначе самый ранний по `created_at` админ) и владелец курса имеют все четыре; снять нельзя.
- Админ пула без поля `perms` имеет все четыре (перенос без потерь).
- Пул: роли `user` и `admin`; `student`/`author` читаются как `user`. Курс: `owner`, `admin`, `author`,
  `member`; `maintainer` читается как `admin`.
- Свою роль и свои галочки не меняет никто; галочку, которой у тебя нет, выдать нельзя.
- Отправка в курс: публичный — любой вошедший; приватный — участник, автор, админ курса, админ пула.
  Сразу встаёт у автора, у админа курса с `content` и у админа пула с `content`; у остальных — предложение.
- Чужой прогресс: админ пула с `progress` — весь; владелец или админ курса с `progress` — студенты
  своего курса и только его задания.
- Интерфейс: «сопровождающий» → «админ». Подписи галочек: «Админы», «Задания и блоки», «Люди и доступ»,
  «Прогресс и решения».
- Пуш в `main` = выкладка на прод: только после полного pytest, ruff и живого прогона.

## Review Focus

- Прод-пользователь с ролью `author` после выкладки: собственные образы (push, вложения, исходники,
  карточка) продолжают работать — проверяется в Task 4 (`test_a_former_author_keeps_its_own_images`).
- Единственный админ пула без `owner` в config: не может лишить прав самого себя и не теряет `admins`
  (Task 1, `test_the_only_admin_is_the_owner`).
- Админ с `admins`, но без `progress`, пытается выдать другому `progress` — 403 (Task 5).
- Старый клиент шлёт `role: maintainer` в `PUT /courses/<o>/<n>/members/<u>` — принимается как `admin`
  (Task 3).
- Админ пула открывает приватный курс, в котором не состоит: видит его и может править при `content`
  (Task 2).
