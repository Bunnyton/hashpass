# Форки и зеркала курсов — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Курс можно скопировать как зеркало (структура всегда как у родителя, люди и прогресс свои) или как форк (своя правка, подтягивание по кнопке, запрос на слияние всего форка в родителя); родитель разрешает/запрещает каждый вид и может удалить существующие копии.

**Architecture:** Чистая логика копий — новый модуль `registry/course_copies.py` (структура, diff, трёхстороннее слияние). Хранение — новые поля `Course` + распространение в зеркала из `CourseStore.edit` (ловит всех писателей) + догоняющее чтение в `CourseStore.get`. Маршруты — новый `registry/course_copy_api.py` рядом с `course_api.py`, права — через `access.can`. Веб — `course_web.py` + `course.html.j2` + `static/api.js` (формы `data-api`). Студент — строка происхождения в TUI и `hashpass courses`.

**Tech Stack:** Python 3.13, Flask, Jinja2, Textual, pytest (маркер `tier1`), ruff.

**Spec:** `docs/superpowers/specs/2026-10-31-форки-и-зеркала-курсов-design.md` (читать целиком перед каждой задачей).

## Global Constraints

- Пуш в `main` = деплой прода. Работать в ветке `course-copies`; в `main` — только по слову пользователя.
- Старые курсы читаются без миграции: `origin = {}`, `allow_mirrors = True`, `allow_forks = False`, `merges = []`.
- Старые клиенты видят зеркало как обычный курс; новые поля в ответах только добавляются.
- «Структура» = блоки `{id, name}` + задания `{repo, tag, n, pinned, added_by}` в порядке + `auto_update`. **Скрытые задания (`hidden: true`) в структуру не входят. `open` блока — не структура.**
- Копия приватного курса — только приватная.
- Тексты для людей — по-русски; никаких «stage/grader» в студенческом тексте.
- Каждая задача: `ruff check src tests` и `pytest tests/registry -m tier1 -q` зелёные перед коммитом.
- Коммит-сабжекты по-английски, в конце `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Две параллельные записи родителя → зеркало получает последнюю структуру, не промежуточную (распространение берёт свежего родителя под замком зеркала).
- Родитель переименован после создания зеркала → ссылка «на основе» и синхронизация не ломаются (всё по `origin.id`).
- Запрос слияния, в котором форк убрал задание, решённое учениками родителя → принятие проходит, прогресс учеников по `repo:tag` остаётся.
- Зеркало, у владельца которого отозван доступ, — ученик через старый клиент не получает задание через это зеркало (`/catalog`, `/task`, `/closure`, `/submit`).
- Удаление родителя, у которого есть зеркало форка → форк `gone`, зеркало форка не трогается и продолжает следовать за форком.

### Task 2: Diff и трёхстороннее слияние

**Files:**
- Modify: `src/hashpass/registry/course_copies.py`
- Test: `tests/registry/test_course_copies.py`

**Interfaces:**
- Consumes: `structure()` из Task 1 (формат dict).
- Produces:
  - `diff(old: dict, new: dict) -> list[dict]` — список изменений, каждое `{"op": ..., ...}`, `op` ∈ `task_add {ref, block, after}`, `task_remove {ref}`, `task_set {ref, field, old, new}` (field ∈ `n`, `pinned`), `task_move {ref, block, after}`, `block_add {id, name, after}`, `block_remove {id}`, `block_rename {id, old, new}`, `block_move {id, after}`, `auto_update {old, new}`. `ref` = `"repo:tag"`, `after` = ref/id предыдущего соседа или `"^"`.
  - `merge3(base: dict, ours: dict, theirs: dict) -> tuple[dict, list[dict]]` — применить `diff(base, theirs)` к `ours`; вернуть (новая структура, конфликты). Конфликт = изменение theirs по элементу, который `diff(base, ours)` тоже менял, и итог отличается; тогда остаётся ours, а изменение уходит в конфликты как есть.
  - `describe(change: dict) -> str` — одна строка по-русски для отчёта/страницы diff («добавлено задание bob/git-init:1 в блок «Git»», «ревизия bob/git-init:1: v2 → v3», …).

Правила позиций (из спеки §3.1): добавленное задание — после того же соседа; соседа нет — в конец блока; блока нет — блок создаётся (с именем из theirs) в конце. `block_remove` у theirs при непустом блоке в ours (ours добавил туда своё) — конфликт.

  - `test_merge3_parent_adds_task_after_neighbour` — base `[A,B]`, theirs `[A,X,B]`, ours `[A,B,C]` → `[A,X,B,C]`, конфликтов нет.

  - `test_describe_russian` — `describe({"op":"task_set","ref":"bob/git-init:1","field":"n","old":2,"new":3}) == "ревизия bob/git-init:1: v2 → v3"`.

**Interfaces:**

Поведение: `CourseStore.edit` запоминает `structure(course)` до `yield`; после сохранения и **снятия** замка, если структура изменилась — `propagate(course.id)`. На зеркале (`kind == "mirror"`) маршруты `POST blocks`, `DELETE blocks/<id>`, `PUT blocks/<id>` с `name`, `PUT layout`, `POST tasks`, `PUT|DELETE tasks/…`, `proposals/…`, PUT курса с `auto_update` → `403 «это зеркало курса <ref> — задания и порядок меняет его автор»`; `PUT blocks/<id> {open}` — можно (ящик `content`). Предложения в зеркале не создаются: `POST tasks` от не-персонала тоже 403 с той же фразой.
