# Стенды (Labfile) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** задание из нескольких машин в изолированной сети (Labfile ≈ docker-compose для Taskfile).

**Architecture:** `hashengine build Labfile` собирает образ каждой машины из её Taskfile, кладёт
дельты не-консольных машин в слой ref-а стенда под `/.hp-nodes/<m>/` + `lab.json`; родитель
стенда — образ консоли. На запуске — держатели netns (`hpn-` машины, они же реле канала
проверки), проводка veth/мостов в netns коммутатора, узлы грузятся в свои netns, консоль —
foreground в своём. Сервер пула не меняется.

**Tech Stack:** Python 3.13, systemd-nspawn/machinectl (sudo NOPASSWD), overlayfs, iproute2
и systemd-socket-proxyd из базы, pytest (tier3 = реальный nspawn), ruff.

**Spec:** `docs/superpowers/specs/2026-11-02-стенды-несколько-машин-design.md` (§1а — главное).

## Global Constraints

- Обычные задания (без Labfile) запускаются побайтно как раньше: сеть хоста, TCP-сервер проверки.
- Никаких изменений сети/iptables/sysctl хоста; только `sudo systemd-nspawn|machinectl|mount|umount|tar|rsync`.
- База (runtime) не меняется — без пересборки/пуша базы.
- Студент не видит `/.hp-nodes`, сокетов, реле (кроме listening `127.0.0.1:$HP_PORT`, как сегодня).
- Пределы: ≤ 8 машин, ≤ 4 сети, ≤ 4 интерфейса на машину; имя машины `[a-z][a-z0-9-]{0,14}`, сети `[a-z][a-z0-9-]{0,11}`.
- Ничего не пушить на prod-пул; демо-задание — скрытое, локально.
- Сообщения автору/студенту — по-русски.

## Review Focus

- Прерванный запуск (Ctrl-C, упавшая проводка) — не оставляет машин `hp*-<pid>-`; следующий `reap_orphans` их убирает → тест в Task 1.
- Две сессии стенда одновременно на одной машине — не мешают друг другу (имена мостов только внутри netns коммутатора) → tier3 в Task 7.
- Команда, набранная в ssh-сессии на узле, не принимает `accept cmd`/derived-стадию консоли и не блокируется политикой консоли → тест в Task 6.
- Ошибка автора в Labfile (две консоли, адрес вне подсети, неизвестная машина в `check live on`) — понятная русская ошибка сборки, не traceback → тесты в Task 3.
- Узел с `gw` вне своих сетей / одинаковые IP — ловит lint до сборки → тест в Task 3.

### Task 3: модель и парсер Labfile

**Files:** Create `src/hashpass/lab/__init__.py`, `src/hashpass/lab/model.py`, `src/hashpass/lab/parse.py`. Test `tests/lab/test_labfile.py`.

**Interfaces — Produces:**
```python
@dataclass(frozen=True) class NetAddr: net: str; addr: str          # "10.0.0.10/24"
@dataclass(frozen=True) class Machine: name: str; build: str | None; image: str | None;
                                       nets: tuple[NetAddr, ...]; gw: str | None; console: bool
@dataclass(frozen=True) class Lab: name: str; version: str; machines: tuple[Machine, ...]
    console -> Machine (property); nodes -> tuple[Machine, ...] (property)
def parse_labfile(text: str) -> tuple[Lab, Recipe]   # Recipe = задачная часть, name/version из `lab`
def load_labfile(path: Path) -> tuple[Lab, Recipe]
def validate(lab: Lab) -> None                       # ValueError с русским текстом
def is_labfile(path: Path) -> bool                   # имя Labfile или каталог с Labfile без Taskfile
```
Разбор: вырезать строку `lab <n>:<v>` и блоки `machine` (отступ), остаток отдать `parse_recipe`
(подставив `image <n>:<v>`); `from`/`run`/`copy` на верхнем уровне Labfile — ошибка
«в Labfile шаги сборки — в Taskfile машины». Внутри `machine`: `console`, `build <путь>`,
`image <ref>`, `net <сеть> <ip/prefix>`, `gw <ip>`; прочее — ошибка.

- [ ] тесты: пример из spec §1а разбирается (2 машины, pc.console, web.nets); stage с `check live on web` даёт check_node; ошибки (каждая — `pytest.raises(ValueError, match=…)`): нет консоли, две консоли, `build` и `image` вместе или ни одного, повтор имени, плохое имя, адрес не IP, разные префиксы одной сети, повтор IP, `gw` вне сетей машины, > 8 машин, > 4 интерфейсов, консоль без `net`, `check live on db` для несуществующей машины, `run` на верхнем уровне.
- [ ] реализация, pytest, commit.

### Task 4: конфиг стенда, маска, проводка (чистые функции)

**Files:** Create `src/hashpass/lab/config.py`, `src/hashpass/lab/wire.py`, `src/hashpass/lab/mask.py`. Test `tests/lab/test_config.py`, `tests/lab/test_wire.py`.

**Interfaces — Produces:**
```python
NODES_DIR = ".hp-nodes"; LAB_JSON = "lab.json"
def lab_to_dict(lab: Lab, *, hosts: bool) -> dict ; def lab_from_dict(d: dict) -> tuple[Lab, bool]
def find_lab(lowers: list[Path]) -> tuple[Lab, bool, Path] | None   # (lab, hosts, слой) верхний с lab.json
def hosts_text(lab: Lab) -> str          # 127.0.0.1 localhost + "<ip> <name>" для каждого адреса
def port_unit(port: int) -> str          # текст hp-port.service (oneshot: /run/hp/port, 0644)
def wire_script(lab: Lab) -> str         # sh для helper-а в netns коммутатора; netns машин = /run/netns/<name>
def ensure_mask(dir: Path) -> Path       # dir с whiteout `.hp-nodes` (char 0:0) через sudo tar; идемпотентно
def console_lowers(lowers: list[Path], mask: Path) -> list[Path]   # [mask, *lowers] если в цепочке есть .hp-nodes
```
`wire_script`: `set -e`; на сеть `ip link add br-<net> type bridge; ip link set br-<net> up`; на интерфейс
k машины i: `ip link add v<i>e<k> type veth peer name eth<k> netns <m>`, `ip link set v<i>e<k> master br-<net> up`,
`ip -n <m> addr add <addr> dev eth<k>`, `ip -n <m> link set eth<k> up`; затем `ip -n <m> route add default via <gw>`.

- [ ] тесты: round-trip lab.json; `find_lab` берёт верхний слой с `.hp-nodes/lab.json`, None без него; `hosts_text` для примера содержит `10.0.0.20 web` и `10.0.0.10 pc`; `wire_script` для router (lan+wan) создаёт оба моста, `v2e1`, `ip -n router addr add 192.168.50.1/24 dev eth1` и default route у db; `console_lowers` без `.hp-nodes` возвращает lowers как есть.
- [ ] реализация, pytest, commit. (`ensure_mask` проверяется tier3 в Task 7.)

**Interfaces — Produces:**

class LabRuntime:
