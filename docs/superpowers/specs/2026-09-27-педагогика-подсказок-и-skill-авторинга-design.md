# Педагогика подсказок + skill авторинга заданий — дизайн

Дата: 2026-09-27. Статус: принят (автономная сессия; допущения помечены).

## 1. Зачем

Задания в `content/tasks/` выдают ответ слишком рано: `on enter say "Наберите: …"`,
`hint tries 2 say "Точно: <команда>"`. Студент не думает, не читает вывод, не гуглит.
Требование автора курса:

- **Никаких прямых подсказок.** Только наводящие вопросы — и то для сложных заданий;
  простые — вообще без подсказок.
- Если студент **реально долго возится** или **несколько раз** не понимает, почему
  «папка не копируется» — «посмотри внимательно на вывод, там есть подсказка».
  Учим читать вывод, `man`, `--help`, гуглить.
- Задание **естественное** и решается естественно (цель, а не «наберите команду»).
- В конце — **прикол**: ASCII-мем или смешная фраза.
- Если что-то реально стоит подсказать — это подсказывается **после нескольких
  самостоятельных попыток**, а не сразу.

## 2. Решения

### 2.1 Движок: `hint` срабатывает один раз за этап

Сейчас `match_rule` — first-match-wins по `>=`, без памяти: после порога подсказка
печатается на **каждой** команде (в т.ч. `neutral`). Лестницу «вопрос → куда смотреть
→ конкретика» так не построить.

Изменение: `TaskSession` помнит, какие правила этапа уже сработали; сработавшее правило
больше не рассматривается. Тогда лестница пишется по возрастанию порогов:

```
hint tries 3  say "…наводящий вопрос…"
hint tries 6  say "…куда смотреть: вывод / man / что загуглить…"
hint tries 10 say "…конкретика (понятие/ключ), если оправдана…"
hint idle 180 say "…долго сидишь — перечитай задание и вывод…"
```

Семантика без изменений: `tries` — попытки без `neutral`; `idle` — секунды с
начала этапа (последнего прогресса), оценивается при очередной команде; `cmd`/`output`
— реактивные; первое совпавшее **ещё не сработавшее** правило побеждает.
DSL не меняется. Тесты tier1: `test_hints.py`, `test_taskrun.py`.

### 2.2 Skill `.claude/skills/task-authoring/`

Skill в репозитории (едет с проектом): педагогика подсказок, тон, справочник DSL
**по парсеру** (`recipe/parse.py`), семантика рантайма, шаблоны, чек-лист проверки
(parse-тест → `hashengine build` → `expect` по живой консоли). CLAUDE.md ссылается
на него.

### 2.3 Переписать все задания в `content/tasks/*/`

Для каждого: формулировка этапа = **цель**; `on enter` — контекст или вопрос, без
команд; лестница подсказок по §2.1; **реактивные** подсказки по выводу там, где
система сама сообщает причину (`cp: -r not specified; omitting directory`,
`grep: … Is a directory`, `find: paths must precede expression`,
`Permission denied`, `Unable to locate package`); brief.md — теория с
**обобщёнными** примерами, без готового ответа на *это* задание; `hp/finale` —
мем/шутка. Механика приёмки (`observe`/`check`/`accept`) не меняется.

### 2.4 Проверка

tier1 + ruff; сборка всех заданий (`content/tasks/deploy.sh --dry`); `expect` по
живой консоли минимум на трёх заданиях (лестница, однократность, реактивная
подсказка, финал). На пул (prod) не выкатывать.

## 3. Допущения (автор не отвечал в сессии)

- Последняя ступень лестницы — понятие/ключ, **никогда** дословная команда.
- Простые вводные задания — один вопрос или без подсказок.
- Версии образов остаются `:1`; перевыкладка на пул — решение автора
  (`hashengine push … --force`).
