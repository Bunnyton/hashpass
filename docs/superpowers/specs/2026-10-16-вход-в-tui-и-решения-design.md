# Вход в TUI, попытки и решения с выводом — дизайн

Дата: 2026-10-16. Статус: одобрен пользователем («Ок, в работу»).

## Цель

1. Студент входит, регистрируется и перелогинивается **внутри** `hashpass` (Textual),
   а не через `input()`/`getpass` до старта TUI. Вход и регистрация — разные формы.
2. Каждый запуск задания — **сессия**: команды студента + их вывод почти вживую уходят
   на пул. Препод на сайте видит попытки до зачёта (чтобы подсказать удалённо).
3. Зачтённая сессия = **решение**. Студент смотрит его локально в TUI (`p`), с выводами.
4. Вход с нового устройства подтягивает решения зачтённых задач.

## Что есть сейчас (опора)

- Вход: `cli._require_pool_identity` (`cli.py:2060`) — терминальные промпты до TUI;
  401 при входе молча уводит в `_register_interactive`. TUI: `tui.PoolTUI`, `run_tui`.
- Токен: `CredentialCache` (`~/.hashpass/creds.json`, TTL 60 дней), `pool.json {url,user}`,
  выход — `forget_variants(_url_variants(url))` + `save_pool(env, url, "")`.
- Команды: гостевой `__hp_postexec` шлёт команду + дельту вывода на grade-сокет;
  `_parse_cmd_request` → `_render_observe` → `history.append({command, ts, typing, pasted})`
  (вывод не сохраняется). `history` создаётся в `_run_task` (`cli.py:982`), отдаётся в
  `on_complete(completed, history)` → `_run_pool_task._submit` → `POST /submit`.
- Сервер: `ProgressStore` `progress/<user>.json {ref: {status, ts, global_key, digest,
  history, authenticity}}` (перезапись последней попыткой). Сайт: матрица `/web`
  (`render_dashboard`, ячейки ✓/✓⚠/✗/·) → `/web/history?user=&ref=` (`render_history`:
  плашки вставок/эталона + таблица команд), только author/admin.

## 1. Вход и регистрация в TUI

Новый модуль `src/hashpass/auth_screens.py`:

- `LoginScreen(Screen)` — карточка по центру (рамка `$accent`, `$panel`), заголовок
  «hashpass», поля: **пул** (предзаполнен из `pool.json`/`$HASHPASS_POOL`), **логин**,
  **пароль** (`password=True`). Кнопки «Войти» (Enter) и «Зарегистрироваться».
  Ошибка — красной строкой под формой, экран остаётся. 401 → «Неверный логин или пароль»
  (без авто-регистрации). Нет связи → «Пул недоступен: …».
- `RegisterScreen(Screen)` — логин (`validate_login` на лету), пароль, повтор, группа,
  комментарий; под формой подсказка про политику пароля и строка
  «Команды и их вывод в заданиях видны преподавателю». Кнопки «Создать аккаунт»,
  «Назад ко входу». 400 (пароль/логин) / 409 («логин занят») / 403 («регистрация закрыта»)
  — текстом в форме.
- Логика без ввода-вывода — в `src/hashpass/account.py`: `login(env, url, user, pw)`,
  `register(env, url, user, pw, group, comment)`, `logout(env, url)`; обе возвращают
  `(user, token)`, бросают `AuthError(message)` с русским текстом. CLI-пути
  (`cmd_pool_login`, `cmd_register`, `cmd_logout`, `_register_interactive`) переходят на них.
- Старт: `cmd_pool_home` на TTY с textual **не вызывает** `_require_pool_identity`.
  `run_tui(env, url, user, token)` принимает `user/token` пустыми; если живого токена нет
  (или `/me` → 401 — аккаунт удалён), `PoolTUI` сначала показывает `LoginScreen`, после
  успеха — каталог. Без TTY/textual — прежний терминальный путь.
- Relogin: клавиша `L`/`Д` (видна всем) → `ConfirmScreen` «Выйти из аккаунта X?» →
  `account.logout` → `LoginScreen`; после входа `self.user/token/client/role` заменяются,
  каталог перезагружается, заголовок обновляется.

## 2. Сессии попыток (почти вживую)

- Запуск задания = сессия с `session_id = uuid4().hex`. `_run_task`/`cmd_run` получают
  необязательный `history` от вызывающего (вместо локального списка) — чтобы аплоадер
  видел записи по мере появления.
- `_render_observe` дописывает в запись `output`: вывод команды (ANSI уже вырезан
  `_extract_output`), обрезанный до **16 КБ** с хвостом `\n…обрезано`.
- `AttemptUploader` (`src/hashpass/attempts.py`): поток-демон; раз в 3 с (и на `close`)
  шлёт новые записи `POST /attempt` `{task_ref, session_id, seq, entries, final?}`, где
  `seq` — индекс первой записи. Сервер принимает только `seq == уже_есть` (иначе 409 с
  текущей длиной → клиент досылает с неё) — идемпотентно. `final` ∈ `passed|abandoned|failed`.
  Ошибки сети не трогают консоль: недосланное пишется в `~/.hashpass/outbox/<session>.json`
  и досылается `flush_outbox()` при старте TUI и после следующего задания.
- `/submit` получает `session_id`; при зачёте сессия помечается `passed`
  (`final` приходит и от аплоадера — порядок не важен).
- Сервер: `AttemptStore` (`src/hashpass/registry/attempt_store.py`),
  `attempts/<user>/<ref-safe>/<session>.json` = `{ref, session_id, started, updated,
  final, entries:[{command, output, ts, typing, pasted}]}`. Лимиты на сервере: вывод
  16 КБ/команду, 1000 команд, 512 КБ/сессию (дальше записи отбрасываются, `truncated: true`),
  на задачу хранятся 30 последних незачтённых сессий; зачтённые не удаляются.
  `ref-safe` — `re.sub(r"[^A-Za-z0-9._-]", "_", ref)`; `ref` хранится внутри файла.
- Сессия «идёт сейчас», если `final` пуст и `updated` < 60 с назад.

## 3. Решения

- Решение задачи = последняя по времени `passed`-сессия.
- `GET /solutions` → `{solutions: {ref: {session_id, at}}}` (только свои).
  `GET /solution/<ref>` → сессия целиком (своя; author/admin — с `?user=`).
- Клиент: при зачёте `_submit` пишет `~/.hashpass/solutions/<ref-safe>.json` (сессия как
  на сервере) рядом с `mark_solved`, до сети.
- Синхронизация (`sync_solutions(env, url, token)` в `attempts.py`): после входа и в
  `_reload_catalog` (фоновый поток) — список с пула, скачать отсутствующие/более новые,
  добавить их ref в `solved.json`.
- TUI: клавиша `p`/`з` на задаче → `SolutionViewer(Screen)` (в `viewer.py`-стиле, vim-клавиши,
  `q`/Esc назад): заголовок `ref · зачтено <дата>`, потом `$ команда` (жирным) и вывод.
  Нет локального решения, но задача зачтена → попытка скачать; нет и на пуле →
  «Решение не сохранено (зачтено до появления этой функции)».
- CLI без TUI: `hashpass solution <номер|ref>` печатает тот же лог.

## 4. Сайт

- Матрица `/web`: ячейка = `·` не выполнялось (нет сессий и нет записи),
  `◐` выполняется (есть сессии/запись, но не зачтено; класс `run`, жёлтый),
  `✓` зачтено (`⚠` у вставок — как сейчас). Ячейки ◐/✓ ведут на `/web/history`.
  Старый `✗` (digest-mismatch) → `◐`.
- `/web/history?user=&ref=`: шапка и плашки сохраняются (считаются по решению, иначе
  по последней сессии). Ниже:
  - «● сейчас решает» + `<meta http-equiv=refresh content=5>`, если сессия идёт;
  - **Решение** (`✓ решение`, развёрнуто) — таблица команд (скорость, вставка, эталон),
    под каждой командой её вывод в `<pre>`;
  - **Попытки** — остальные сессии, новые сверху, `<details>`: «дата · длительность ·
    N команд · итог (вышел / идёт / не принято)», внутри та же таблица с выводами;
  - сессий нет, но есть старая запись `progress` → прежняя таблица команд без вывода.
- Права как сейчас: страница только для author/admin. Jinja autoescape.

## 5. Ошибки и совместимость

- Старый клиент → новый сервер: `/submit` без `session_id` работает как раньше.
- Новый клиент → старый сервер: `/attempt` 404 → аплоадер замолкает до конца сессии
  (без outbox), `/solutions` 404 → синхронизация пропускается молча.
- Решения/попытки удаляются вместе со студентом (`/web/users/delete`).
