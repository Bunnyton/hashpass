# Блок «Процессы» — дизайн

Пользователь, 2026-11-01 (скрин `proc-audit`, «Запусти в фоне один sleep 600…»): «В задании нет
чёткого объяснения, что такое фоновые процессы, что такое обычные процессы, как запускать фоновые,
убийство и т.п. Отдельный блок процессы — в нём подробно всё это изложи и придумай задания. Очень
важно раскрыть, что такое системные процессы, службы, поиграться с /etc/hosts и другими systemctl.
Поубивать процессы, попользоваться top, htop, bashtop и др. Объяснить виды сигналов, copy-on-write,
поотправлять разные сигналы, устроить зомбиапокалипсис — поубивать зомби-процессы. Возьми критиком
codex».

## Место в курсе

`bunnyton/linux`: блок «Пакеты и процессы» становится «Пакеты» (apt-update apt-remove apt-add-repo
apt-deb), сразу за ним — новый блок **«Процессы»**. До него пройдены: файлы, конвейер `|`, `>`,
`>>`, `grep`, `find`, `xargs`, `sudo`, права, `apt`, `dpkg -s`, `| sudo tee` (apt-add-repo).
vim ещё **не** пройден → `/etc/hosts` правится `echo … | sudo tee -a`.

Каждое задание — `theory.md` (нулевой уровень, «что, зачем, почему», пошагово — как в Docker/Git,
пользователь просил «подробно изложи») + короткий `brief.md` с базой для первой попытки; дальше
дозы по ошибкам (`hint output … read`, `on enter read`). Процессы живут только в работающей
консоли → приёмка `check live` (скрипты проверки — `/usr/local/lib/hp-proc/`, читаемы всеми).
Демоны-«персонажи» — perl (`perl-base` — Essential в Debian, есть в базе), запускаются systemd
(`User=student`, чтобы студент мог их убивать без sudo) или самим студентом.

## Задания (порядок)

1. **proc-audit** (переписан: `ps`, `pstree`, PID/PPID, системные процессы).
   theory.md: программа vs процесс; PID, PPID, дерево; `ps`, `ps aux` и его столбцы, `ps -ef`;
   `/proc/<PID>`; PID 1 = systemd (в контейнере ядерных потоков `[kthreadd]` не видно — сказано
   словами); демоны/службы — процессы без терминала; пользовательские vs системные (USER root).
   Шаги: (1) поставить psmisc + `Status:` в файл (как было); (2) `pstree` — записать в
   `~/init.txt` имя процесса с PID 1 (`observe`; `systemd`); (3) сколько процессов в системе
   работают от root → нет, плавает. Заменить на: (3) найти PID службы `cron`-подобного демона
   `watchdogd`(наш perl) и его родителя → `~/parent.txt` = `1`. Финал.
   Фоновый `sleep`-подсчёт уходит в задание 2 (там объяснено).

2. **jobs** — передний план и фон.
   Персонаж: `/usr/local/bin/backup` (perl: «копирует» 20 минут, печатает прогресс раз в 10 с).
   theory: терминал занят процессом переднего плана; Ctrl+C = SIGINT (кратко, подробно — в 3);
   `&` — в фон сразу; `jobs`, `%1`.
   Шаги: (1) «Запусти backup так, чтобы терминал остался свободным» — студент чаще всего
   запустит без `&` → терминал занят → Ctrl+Z → `[1]+ Stopped` → `hint output "Stopped" read
   stopped.md` (Ctrl+Z = SIGTSTP, процесс на паузе, `bg`/`fg`, `jobs`). Принято: живой `backup`
   студента не в состоянии T (`check live`). (2) «Верни backup на передний план и останови его»
   — `fg` + Ctrl+C. Принято: `accept cmd "fg"` + `check live` нет backup. (3) «Запусти два
   sleep в фоне и убей только второй» → `kill %2`; `check live`: ровно один sleep студента.
   on pass: `nohup`/`disown` — фон умирает с терминалом (SIGHUP).

3. **signals** — сигналы.
   Персонаж: служба `radio` (perl, `User=student`): ловит HUP — перечитывает
   `/home/student/radio.conf` и пишет в журнал `~/radio.log`; USR1 — пишет в журнал статистику;
   TERM — игнорирует («эфир не прерывают»); STOP/CONT — пауза.
   theory: сигнал = короткое сообщение ядра процессу; `kill -l`, номера; таблица HUP INT QUIT KILL
   TERM USR1 STOP CONT TSTP CHLD; что можно перехватить, что нет (KILL, STOP); `kill`, `pkill`,
   `killall`; по умолчанию TERM.
   Шаги: (1) поменять станцию в `radio.conf` и заставить radio перечитать конфиг **не
   перезапуская** (PID тот же) — `check live` журнал «станция: <новая>» + PID = прежний;
   (2) поставить на паузу — state T; (3) снять с паузы; (4) выключить — TERM не помогает (журнал
   «эфир не прерывают» → доза: KILL, почему последнее средство — останется `/tmp/radio.lock`);
   принято: процесс мёртв. on pass: lock-файл остался — вот почему -9 последнее средство.

4. **top** (как есть).

5. **htop-btop** — htop и btop (bashtop).
   Персонажи: служба `farm` (perl) — родитель + 6 воркеров, один (`worker-3`) ест CPU.
   Шаги: (1) поставить htop и btop (`dpkg -s` статус, `observe bool /usr/bin/htop /usr/bin/btop`);
   (2) в htop найти обжору и поставить его на паузу (F9 → SIGSTOP), не убивая (kill/pkill/killall
   заблокированы; `check live` state T у worker-3); (3) в btop — убить всю ферму одним сигналом
   родителю? Нет: родитель при TERM гасит воркеров — проверка: нет farm-процессов; `ps` открыт.
   on pass: дерево (F5 в htop) показывает родство.

6. **services** — службы, systemctl, journalctl, /etc/hosts.
   Сюжет: внутренний сайт `http://wiki.corp:8471` не открывается. curl есть (`run apt-get install
   curl`), сайт — busybox httpd через юнит `wiki.service` (выключен, не enabled), порт занят
   чужим процессом `squatter` (perl, держит 8471).
   theory: служба = демон под присмотром systemd; юнит-файлы `/etc/systemd/system`,
   `/lib/systemd/system`; `systemctl status/start/stop/restart/enable/disable/is-active`;
   `journalctl -u`; DNS и `/etc/hosts` (первым смотрят hosts — `/etc/nsswitch.conf`).
   Шаги: (1) `curl wiki.corp:8471` → «Could not resolve host» → добавить в /etc/hosts
   (`check live getent hosts wiki.corp` = 127.0.0.1); (2) «Connection refused» → запустить
   службу → она падает: `journalctl -u wiki` «Address already in use» → доза: кто держит порт
   (`ss -ltnp`/`fuser 8471/tcp` из psmisc) → убить squatter → `systemctl start wiki`; принято:
   `curl` отдаёт страницу (`accept output` фразы со страницы + `check live is-active`);
   (3) сайт должен подниматься после перезагрузки — enable (`check live is-enabled`).
   Порт 8471: сеть консоли = сеть компьютера, берём редкий порт.

7. **cow** — fork и copy-on-write.
   Персонаж: `clones` (perl, запускает студент или служба): родитель заполняет 200 МБ, делает
   fork ×5 (`$0 = "clone"`), один клон переписывает свою память — получает собственную копию.
   theory: как запускается любая команда (fork → exec), что fork копирует «всё», почему это
   дёшево — copy-on-write по страницам; RES/VIRT/SHR в top, почему сумма RES больше всей
   памяти; `/proc/<PID>/smaps_rollup`: Rss / Pss / Private_Dirty / Shared.
   Шаги: (1) посмотреть `free -m` и RES клонов в top — вопрос «шесть процессов по 200 МБ, а
   занято ~200 МБ»: записать в `~/used.txt` … плавает → вместо этого (1) найти клона, у которого
   своя копия памяти (Private_Dirty большой), и остановить его, остальных не трогать
   (`check live`: тот самый мёртв, остальные живы); `hint output` нет. on pass: так работают
   redis BGSAVE, PostgreSQL, Android zygote.

8. **zombies** — зомби-апокалипсис (финал блока).
   Персонаж: служба `necromancer` (perl, `User=student`, `Restart=always`): плодит детей, которые
   сразу умирают, а он их не хоронит (не делает wait) → 66 зомби `<defunct>`.
   theory: жизнь процесса: fork → exec → exit → **зомби** до wait() родителя → исчезает; сирот
   усыновляет PID 1 (или subreaper) и хоронит; зомби не убить — он уже мёртв; лечат родителя.
   Шаги: (1) посчитать зомби → `~/zombies.txt` (66, постоянное число — `check live` сравнивает
   с фактическим); (2) «Убей зомби» — студент шлёт kill -9 зомби → ничего (`hint cmd kill read
   undead.md`: мёртвого не убить; кто их родитель? `ps -o ppid`); принято: зомби нет;
   systemd перезапускает necromancer → зомби снова (Restart=always, 15 с) →
   (3) «Они вернулись» → `sudo systemctl stop` + `disable` (`check live` inactive + disabled +
   0 зомби). on pass/финал — мем про зомби.

## Проверки

Все шаги про процессы — `check live <скрипт>`; скрипты в образе (`/usr/local/lib/hp-proc/*`,
0755), первая строка — почему не `observe`. Файловые результаты (`install-status.txt`,
`init.txt`) — `observe`. Пакеты — `observe bool`.

## Риски

- Ctrl+Z/`fg`/job control в консоли (bash в pty через script) — проверить вживую первым делом.
- `hint output "Stopped"` — сообщение bash о приостановке приходит вне вывода команды? Проверить.
- Порт 8471 на машине автора/студента может быть занят — проверка порта перед стартом не нужна,
  редкий порт.
- Сборка (деривация `solve`) идёт без systemd → `solve` шагов `check live` не деривируется,
  но выполняется как подготовка следующих: держать их безвредными.

## Решения после критики Codex (2026-11-01)

Codex (gpt-5.6, 50 замечаний) — принято:
- **proc-audit** без «плавающих» шагов: (1) psmisc, (2) имя процесса с PID 1 → `~/pid1.txt`,
  (3) от чьего имени работает служба `sentry` → `~/sentry-user.txt` (системный пользователь
  `daemon`). Подсчёт `sleep` уходит в jobs, где фон объяснён.
- **jobs**: (1) backup в фоне сразу (`&` из брифа); (2) второй backup — обычным запуском, потом
  освободить терминал, не останавливая (доза при входе: Ctrl+Z, `jobs`, `bg`, `fg`); принято —
  два живых backup, ни один не в T; (3) `fg` + Ctrl+C — остался один; (4) последний — по номеру
  задания (`block kill unless "%"`).
- **signals**: шаги ждут запись в журнале (проверка с повтором), «выключи» — после TERM доза
  о том, что сигнал доставлен, но перехвачен; KILL снимает.
- **htop-btop**: farm при TERM сначала будит детей (CONT), иначе висит на остановленном воркере;
  `KillMode=mixed`; шаги по имени `farm-worker` + наибольшее процессорное время.
- **services**: busybox и legacy-api слушают только `127.0.0.1:8471`; проверка сайта — `curl` с
  повтором; автозапуск = wiki enabled, legacy-api disabled.
- **cow**: цель — убить клона с собственной копией памяти; приняты: все клоны в cgroup
  `clones.service` с `Private_Dirty` < 64 МБ и их ровно пять.
- **zombies**: число сверяется с живым числом Z в момент проверки; зомби — только потомки
  necromancer.
- Во всех заданиях блока — запрет `kill … -1` (убить всё) и `pkill/killall -u`.

Отклонено: «Restart=always не вернёт зомби» — возвращает: перезапуск идёт, когда студент убил
necromancer (главный процесс завершился); это и есть шаг 3. PGID/SID-урок — вне объёма.
