# Модуль «Продвинутый bash» — дизайн

Пользователь, 2026-11-03: «Также отдельно хочу хороший продвинутый модуль по bash скриптам — в нём
основные циклы и приколы bash, проблемные места подсветить. Найти ошибку — поправить несколько
разных bash скриптов. Пописать самим, чтобы решить задачу, объявить массив и т.д.» + «В bash
скриптах отдельно в начале … переменные окружения, объяснить что это такое и что встречается в
разных языках, вывести их, задать свои. Потом рассказать про PATH, положить символьную ссылку в
/usr/local/bin посмотреть, что происходит, а потом целую папку bin прописать в PATH и сделать
source.» + «А в bash скриптах ещё раз повторить, но уже написать свою службу.»

Материалы пользователя (в «Источники» wiki): denysdovhan/bash-handbook, awesome-lists/awesome-bash,
cheatsnake/bash-scripts-by-example (README_RUS).

## Место в курсе

`bunnyton/linux`, новый блок **«Bash-скрипты»** сразу за блоком «Скрипты» (my-command, my-service).
**Решение:** не вливать в «Скрипты» — там вводные задания, которые пользователь хочет «пораньше»;
модуль — продолжение («ещё раз повторить, но уже свою службу»).

К этому месту пройдены: файлы и каталоги, `ln -s` (links), `|`, `>`, `>>`, `2>/dev/null`, `grep`,
`find`, `xargs`, `sudo`, `chmod +x`, права, `apt`, процессы и сигналы, `systemctl`/`journalctl`,
юнит-файлы (services, my-service), vim, регулярки, скрипт в `/usr/local/bin`, `#!`, переменные,
`$(( ))`, `$( )`, `||`, `echo $PATH`, `which` (my-command), `while true` + юнит + `Restart=`
(my-service).

Не дублируем: my-command (своя команда в `/usr/local/bin`), my-service (вечный цикл + юнит +
enable + Restart), regex*, streams, pipes, xargs. Блок «Возможности Linux» (параллельно) даёт
which/type и FHS — у нас PATH глубже: свой `~/…/bin`, `~/.bashrc`, `source`, ловушки PATH.

## Факты рантайма, на которые опирается модуль (проверено вживую, 2026-11-04)

- Консоль запускает `bash --rcfile /etc/hp-bashrc -i`: **`~/.bashrc` при входе не читается**, его
  читает только новая интерактивная оболочка (`bash`). Это и есть сюжет `source`: правка в
  `~/.bashrc` сама в текущую оболочку не попадает. В доме студента есть `~/.bashrc` из skel.
- `env` в консоли: `HOME=/home/student`, `PATH=/usr/local/bin:/usr/bin:/bin:…`, `LANG=C.UTF-8`,
  `SHELL=/bin/sh` (из-за записи сеанса) и служебные `HP_PORT`, `HP_GREETED` — о них молчим.
- Цикл, набранный прямо в консоли, идёт ~25 мс на итерацию (хук проверки на каждую простую
  команду): 100 итераций ≈ 2.5 с. Данные для циклов — 100–200 файлов, не тысячи. Скрипт
  (дочерний bash) этого хука не несёт.
- В базе есть `perl`, `file`, `tree`, `less`, `runuser`; нет `python3`, `shellcheck`, `dos2unix`
  (ставим в `run`, где нужно).
- Консоль сообщает о последней простой команде; у `CITY=X weather` первое слово — присваивание,
  поэтому `accept cmd "weather"` его не узнает → приёмка таких шагов по выводу (`accept output`).

## Задания (порядок)

Каждому — `brief.md` (база), дозы `hp/*.md` по ошибкам, `on pass`, финал-мем, `README.md`,
`wiki.md` (теги, настоящие выводы, `## Источники` со ссылками пользователя где уместно).

### 1. `bash-env` — переменные окружения

Задумка: окружение — список `ИМЯ=значение`, который процесс получает от родителя; так настраивают
программы на любом языке (C `getenv`, Python `os.environ`, Node `process.env`, Go `os.Getenv`).
Персонаж — программа `weather` (perl, `/usr/local/bin/weather`): без `CITY` в окружении ругается
«в окружении нет CITY», с ним печатает детерминированный прогноз; `UNITS=F` — в Фаренгейтах.

Бриф: что такое окружение; `env`/`printenv`, `printenv ИМЯ`, `echo $ИМЯ`; своя переменная
`ИМЯ=значение`. Про `export` — ни слова (ловушка задания).

Шаги:
1. «Покажи все переменные окружения своей оболочки» — `accept output "^HOME=/home/student$"` +
   `accept output "^PATH=/"` (env, printenv). on pass: HOME/USER/PATH/LANG — их задала система при
   входе; программы читают их сами.
2. «weather не знает, где ты. Скажи ей, что ты в Казани, и покажи прогноз» — студент пишет
   `CITY=Казань`, `weather` → «в окружении нет CITY» → `hint output "нет CITY" read export.md`
   (переменная оболочки ≠ окружения; `export`; дети наследуют копию, родителю не вернуть).
   Приёмка `accept output "^Казань: "`.
3. «Покажи погоду в Мурманске в Фаренгейтах — только для этой команды: потом weather снова про
   Казань и в Цельсиях» — `accept output "^Мурманск: .*°F"`.
4. (без текста, та же цель) — `accept output "^Казань: .*°C"`. Если студент сделал `export
   CITY=Мурманск`, тут увидит Мурманск → `hint output "Мурманск" read prefix.md` (`ИМЯ=зн команда`,
   `env`). on pass последнего — факт: weather написана на Perl и читает `%ENV`; в других языках…

### 2. `bash-path` — PATH, ссылка в /usr/local/bin, свой bin + source

Данные: `~/projects/todo/todo` (bash: `todo add …`, `todo` — список из `~/.todo`); `~/tools/bin/`
— пять скриптов (`cheat` — шпаргалка из `~/tools/share/cheat/<cmd>`, `calc`, `stamp`, `mkpass`,
`weekday`).

Бриф: как оболочка ищет команду по PATH (напоминание my-command), `which`/`type`, ссылка на файл
вместо копии (links уже пройден).

Шаги:
1. «Пусть ~/projects/todo/todo запускается откуда угодно просто как todo — символьной ссылкой в
   /usr/local/bin» — `observe /usr/local/bin/todo` (ссылка на абсолютный путь) + `accept cmd
   "todo" ok`. Ловушки: относительная цель (`ln -s projects/todo/todo …`) → висячая ссылка →
   `hint output "No such file or directory" read relative.md`; без sudo → `Permission denied`;
   жёсткая ссылка/копия → `hint cmd ln missing -s`.
2. «Посмотри, что на самом деле лежит в /usr/local/bin под именем todo и куда оно ведёт» —
   `accept output "todo -> /home/student/projects/todo/todo"` (`ls -l`) или `readlink`
   (`accept output "^/home/student/projects/todo/todo$"`): два варианта, одна регулярка с `|`.
   on pass: правишь оригинал — меняется и команда; удалишь оригинал — ссылка повиснет.
3. «Скриптов в ~/tools/bin много — ссылку на каждый делать скучно. Пусть весь каталог будет в
   PATH в каждой новой оболочке — и в этой тоже, без перезахода. Проверь: cheat tar» —
   `accept file /home/student/.bashrc "PATH=.*tools/bin"` + `accept output "^tar "` (вывод
   cheat). Дозы: `cheat: command not found` после правки `.bashrc` → `source.md` (кто читает
   `~/.bashrc`, `source`/`.`); `command not found` у любой другой команды → `overwrite.md`
   (`PATH=~/tools/bin` затёр PATH: `PATH=$PATH:…`, починить — `PATH=/usr/bin:/bin` или новая
   оболочка). on pass: в Debian `~/.profile` сам добавляет `~/bin` и `~/.local/bin`, если они есть.

### 3. `bash-loops` — циклы и кавычки (фотоархив)

Данные: `~/photos/` — ~150 снимков `2023-07-14 Сочи 001.JPG`, … (пробелы в именах, разные годы),
несколько уже `.jpg`; `~/photos/delete.txt` — 12 имён на удаление.

Бриф: `for x in …; do …; done` на примере `for f in *.txt`, `$f`; `${f%.txt}` — отрезать хвост.
Кавычки — не трогаем (ловушка).

Шаги:
1. «Переименуй все .JPG в ~/photos в .jpg — остальное в имени как было» — `observe
   /home/student/photos`. Ловушки: `mv *.JPG *.jpg` → `target '*.jpg': No such file…`/`is not a
   directory` → `mv-glob.md` (mv не переименовывает пачкой, нужен цикл); без кавычек `mv $f …` →
   `cannot stat '2023-07-14'` → `quotes.md` (разбиение на слова, `"$f"`); `for f in $(ls)` — то
   же.
2. «В delete.txt — снимки на удаление, по имени в строке. Удали их» — `observe
   /home/student/photos`. Ловушка: `for n in $(cat delete.txt)` / `xargs rm` → снова «cannot
   remove '2023-07-14'» → `while-read.md` (`while IFS= read -r line; do …; done < файл`).
3. «Разложи снимки по каталогам годов: ~/photos/2023/…, 2024/…» — `observe /home/student/photos`;
   `on enter read substr.md` (`${f:0:4}`, `mkdir -p`).

### 4. `bash-if` — коды возврата и условия (проверка бэкапов)

Данные: `~/backups/` — 40 архивов `site-2026-10-01.tar.gz` …: целые, битые (обрезанные), пустые
(0 байт), разного размера.

Бриф: код возврата `$?` (0 = успех), `if команда; then …; else …; fi`; `gzip -t` проверяет архив.

Шаги:
1. «Для каждого архива напечатай OK имя или BROKEN имя» — `observe output` + `similarity 100`.
   Ловушка: `if [ gzip -t $f ]` → `[: -t: binary operator expected` → `bracket.md` (`[` — это
   команда `test`; `if` смотрит на код любой команды).
2. «Пустые архивы отметь EMPTY, остальные — как раньше» — `observe output`; `on enter read
   tests.md` (`[ -s f ]`, `-f -d -e`, `elif`). Ловушка `[ -s $f ]` без кавычек — имена без
   пробелов, не бьёт; `[$x]` без пробелов → `[-s: command not found` → `spaces.md`.
3. «Покажи только целые архивы больше 1 МБ» — `observe output`. Ловушка: `[ $size > 1000000 ]` —
   `>` перенаправление: появится файл `1000000`, «больше» станет истиной → подсказка-вопрос «не
   появилось ли в ~/backups новых файлов?» → `numbers.md` (`-gt`, `(( ))`, `[[ ]]` vs `[ ]`).

### 5. `bash-arrays` — массивы

Шаги:
1. Дежурства: `~/duty/team.txt` — 7 человек «Имя Фамилия», `~/duty/days.txt` — 30 дат. «Покажи
   график: дата и дежурный по кругу» — `observe output` + `similarity 100`. Бриф: массив
   `a=(x y z)`, `${a[i]}`, `${#a[@]}`, `"${a[@]}"`, `$(( i % n ))`. Ловушка: `team=($(cat
   team.txt))` → 14 элементов → `hint tries`/вопрос «сколько человек в массиве?» → `mapfile.md`
   (`mapfile -t`, `IFS`).
2. «Сколько неудачных входов с каждого адреса в ~/duty/auth.log? По строке «адрес число» — без
   sort и uniq» — `observe output` + `similarity 100`; `block sort|uniq match "."`;
   `on enter read assoc.md` (`declare -A`, `((n[$ip]++))`, `"${!n[@]}"`).

### 6. `bash-debug` — найди ошибку

`~/broken/` — четыре сломанных скрипта; каждый шаг — починить один, запустить, вывод совпадает с
эталоном (`observe output` + `similarity 100`; эталон — `solve` с исправленной копией). Бриф: как
искать: прочитать сообщение (имя файла и номер строки), `bash -x скрипт`, `shellcheck скрипт`
(ставим в образ). Скрипты (каждый — своя классическая ловушка):
1. `report.sh` пришёл из Windows: `\r` в конце строк → `$'\r': command not found` / `bad
   interpreter` → `crlf.md` (`cat -A`, `sed -i 's/\r$//'`).
2. `count-errors.sh` всегда пишет «Ошибок: 0» — `cat … | while read …; do n=$((n+1))` — счётчик в
   подоболочке конвейера → доза `subshell.md` по `hint tries`/вопрос.
3. `ext.sh` — функция «возвращает» строку через `return` → `numeric argument required` →
   `return.md` (return — только код 0–255, строку — `echo` + `$( )`, `local`).
4. `cleanup.sh --dry-run` показывает, что удалил бы **весь корень**: опечатка в имени переменной
   (`$CACHE_DIR` vs `$CAHCE_DIR`) → пустая строка → `rm -rf /*` (история Steam, 2015) →
   `set-u.md` (`set -euo pipefail`, `${VAR:?}`). Скрипт только печатает (`echo rm …`), ничего не
   удаляет.

### 7. `bash-script` — свой скрипт: backup

Пиши `/usr/local/bin/backup` (или любой каталог PATH). Приёмка — `check exec hp/test-backup`:
скрипт запускается от student на скрытом наборе каталогов (не тех, что видит студент), проверяются
архивы и коды выхода (только так: программу студента не проверить `observe`).

Шаги:
1. «backup каталог… — каждый каталог в ~/backups/<имя>-<дата_время>.tar.gz» — цикл по `"$@"`,
   `basename`, `date +%F_%H%M%S`. Бриф: `$1`, `$@`, `$#`, `"$@"` (с пробелами), `basename`.
2. «Без аргументов — объясни, как пользоваться, и выйди с ошибкой; несуществующий каталог —
   сообщи, остальные всё равно упакуй, а в конце выйди с ошибкой» — `exit 1`, `>&2`,
   `[ -d ]`, переменная-флаг. `on enter read exit.md`.
3. «Храни по три последних архива каждого каталога — старые удаляй» — массив из glob:
   `old=(~/backups/site-*.tar.gz)`, `${#old[@]}`, срез `"${old[@]:0:n-3}"`. `on enter read
   rotate.md`.

### 8. `bash-service` — служба на своём скрипте

Служба `sorter`: раз в 2 секунды разбирает входящий каталог по расширениям, пишет в журнал, что
куда переложила; где разбирать — из `/etc/default/sorter` (`EnvironmentFile=`, мост к bash-env);
на остановку — итог в журнал (`trap … TERM`). Приёмка — `check live` скриптом
`/usr/local/lib/hp-proc/check-sorter run|env|stop` (служба живёт только в работающей консоли).

Шаги:
1. «Заведи службу sorter: раз в 2 секунды она разбирает ~/inbox — картинки (.jpg .png) в
   ~/inbox/images, документы (.pdf .txt) в ~/inbox/docs, остальное в ~/inbox/other» — check:
   активна, подложенные файлы разобраны за ≤ 8 с, владелец student (`User=student`). Дозы:
   203/EXEC (my-service), `case` для расширений в брифе.
2. «Пусть каталог служба берёт из /etc/default/sorter (INBOX=…), а не из скрипта: разбирай
   ~/drop» — check: в файле `INBOX=/home/student/drop`, юнит с `EnvironmentFile`, разбирает
   `~/drop`. Доза `envfile.md` (`EnvironmentFile=`, `Environment=`, `daemon-reload`).
3. «Остановка — культурно: на systemctl stop служба пишет в журнал, сколько файлов разобрала, и
   выходит» — check: inactive и в журнале последнего запуска строка `разобрано N`. Доза `trap.md`
   (`trap 'echo …; exit 0' TERM`; ловушка: `sleep` в переднем плане — trap ждёт, `sleep & wait`).

## Решения

Вычитка codex (2026-11-04), принято:

- **Место:** блок «Bash-скрипты» сразу за «Скрипты» — подтверждено. Порядок заданий тоже.
- **bash-env, шаг 3 «только для одной команды»:** codex — постоянный `export` даёт тот же вывод.
  Решение: шаг 4 без текста (weather снова Казань в °C) и есть проверка, что окружение оболочки не
  тронуто; кто экспортировал Мурманск, увидит его там и получит дозу `prefix.md`.
- **bash-path, шаг 3:** проверять, что системный PATH сохранён: строка в `~/.bashrc` должна
  содержать и `$PATH`, и `tools/bin` (регулярка), а не только `tools/bin`; затёртый PATH ловит доза
  `overwrite.md`.
- **bash-loops:** `observe` каталога сравнивает точный набор файлов — удаление «всего» или не тех
  не пройдёт. `${f:0:4}` не в `on enter`: обобщённый пример подстроки — в брифе рядом с `${f%…}`
  (семейство `${…}`), доза — только после упора.
- **bash-if:** пустые архивы — до `gzip -t` (так и в эталоне); три шага оставлены, но каждый
  приносит одну мысль (код возврата → проверки файлов → числа). Захардкодить 40 строк без проверки
  нельзя: какие архивы битые, видно только проверкой.
- **bash-arrays:** `observe output` сравнивает множеством → к нему `accept output` на точное число
  строк. `sort`/`uniq` закрыты `block`.
- **bash-debug:** `shellcheck` ставится в `run`; итоговая доза `set-u.md` говорит и про
  `pipefail`.
- **bash-script:** скрытые каталоги в проверке (в т. ч. с пробелом в имени); массив не
  проверяется — цель «три последних» проверяется поведением.
- **bash-service:** проверка требует `ExecStart` на файл-скрипт (не `bash -c`), `User=student` и
  `EnvironmentFile=`; итог в журнале — одна строка на остановку.
