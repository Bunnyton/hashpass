# Экскурсия по корню: описание задания

## Что добавляет pull request

Pull request добавляет вводное задание `root-tour` и включает его в блок «Знакомство» сразу после `cd-abs`.

Новые файлы:

- `content/tasks/root-tour/Taskfile` — сценарий и правила автоматической проверки;
- `content/tasks/root-tour/brief.md` — вводная теория о корне `/`;
- `content/tasks/root-tour/etc.md` — пояснение каталога `/etc`;
- `content/tasks/root-tour/home.md` — пояснение каталога `/home`;
- `content/tasks/root-tour/proc.md` — пояснение виртуальной файловой системы `/proc`;
- `content/tasks/root-tour/dev.md` — пояснение файлов устройств в `/dev`;
- `content/tasks/root-tour/hp/finale` — цветной финал задания.

В `content/tasks/deploy.sh` идентификатор `root-tour` добавлен после `cd-abs`. Благодаря этому студент уже знает `ls`, `cat`, `ls -l`, абсолютные пути и переходы по каталогам, но ещё не приступил к изменению файлов.

## Учебная цель

Студент знакомится с устройством корневой файловой системы Linux и понимает назначение пяти важных точек:

- `/` — начало единого дерева файловой системы;
- `/etc` — общесистемные настройки;
- `/home` — домашние каталоги обычных пользователей;
- `/proc` — создаваемые ядром сведения о системе и процессах;
- `/dev` — интерфейсы устройств в виде специальных файлов.

Задание не требует новых команд. Оно закрепляет уже изученные `ls`, `cat` и `ls -l` на реальных системных объектах.

## Сборка и запуск

Из корня репозитория:

```bash
hashengine build content/tasks/root-tour/Taskfile
hashpass run root-tour:1
```

Если `hashengine` не установлен как команда:

```bash
python3 -m hashengine build content/tasks/root-tour/Taskfile
hashpass run root-tour:1
```

Для автоматического прогона эталонного решения:

```bash
TMPDIR=/var/tmp/hp-pytest python3 docs/examples/author_playground.py content/tasks/root-tour/Taskfile
```

Для сборки и запуска необходимы Linux, `systemd-nspawn`, настроенный scoped sudo и базовый rootfs проекта.

## Полный сценарий: ввод и ожидаемый вывод

Точные версии ядра и дистрибутива, даты и состав каталогов зависят от базового образа. `solve` задаёт эталонное действие. Первые четыре цели сравнивают вывод через `observe output` со 100% совпадением после штатной нормализации списков. Текст команды не проверяется, поэтому допускается любое равнозначное решение. На первом и третьем шагах нужно перейти в каталог, содержимое которого изучается: движок распознаёт имена из `ls` как пути относительно текущего каталога. Для `/dev/null` применяется `accept output`: оно проверяет устойчивые поля подробного вывода и не зависит от времени изменения файла.

### 1. Корень `/`

Студент видит цель:

> Перейди в / и посмотри, какие каталоги начинаются от корня файловой системы

Ввод:

```bash
cd /
ls
```

Характерный вывод:

```text
bin  boot  dev  etc  home  lib  proc  root  run  tmp  usr  var
```

Условие успеха: после перехода в `/` команда выводит тот же список, что эталонный `ls`.

После успеха:

> Косая черта — вершина всего дерева. Следующая остановка — настройки системы.

### 2. Сведения о системе в `/etc`

Перед целью показывается пояснение о назначении `/etc` и файле `/etc/os-release`.

Студент видит цель:

> Узнай название и версию системы из /etc/os-release

Ввод:

```bash
cat /etc/os-release
```

Характерный вывод:

```text
PRETTY_NAME="Debian GNU/Linux ..."
NAME="Debian GNU/Linux"
VERSION_ID="..."
ID=debian
```

Условие успеха: вывод совпадает с содержимым `/etc/os-release`, полученным эталонным решением.

После успеха:

> Название системы хранится обычным текстом. Следующая остановка — пользовательские данные.

### 3. Домашние каталоги в `/home`

Перед целью объясняется отличие домашних каталогов обычных пользователей от `/root`.

Студент видит цель:

> Перейди в /home и посмотри, чьи домашние каталоги там есть

Ввод:

```bash
cd /home
ls
```

Ожидаемый основной элемент вывода:

```text
student
```

Условие успеха: после перехода в `/home` команда выводит тот же список домашних каталогов, что эталонный `ls`.

После успеха:

> У каждого пользователя может быть свой дом. Дальше — каталог, которого нет на диске.

### 4. Ядро через `/proc`

Перед целью объясняется, что `/proc` — виртуальная файловая система, содержимое которой создаёт ядро.

Студент видит цель:

> Узнай версию ядра из /proc/version

Ввод:

```bash
cat /proc/version
```

Характерный вывод:

```text
Linux version ...
```

Условие успеха: вывод совпадает со сведениями из `/proc/version`, полученными эталонным решением.

После успеха:

> /proc создаёт ядро на лету. Последняя остановка — устройства.

### 5. Устройство `/dev/null`

Перед целью объясняется, что Linux представляет многие устройства специальными файлами и что записанные в `/dev/null` данные исчезают.

Студент видит цель:

> Посмотри подробную информацию о /dev/null

Эталонный ввод:

```bash
ls -l /dev/null
```

Характерный вывод:

```text
crw-rw-rw- 1 root root 1, 3 ... /dev/null
```

Условие успеха: одна строка вывода содержит тип символьного устройства `c`, владельца и группу `root`, номера устройства `1, 3` и путь `/dev/null`. Время изменения не сравнивается: контейнер может создавать `/dev/null` заново для отдельных запусков. Текст введённой команды не проверяется.

После успеха:

> Первый символ c означает символьное устройство: /dev/null принимает данные и ничего не сохраняет.

Затем запускается цветной финал с выводом:

> / — это начало всего дерева Linux.

## Нейтральные команды и ошибки

`pwd` и `clear` разрешены как нейтральные команды: они не продвигают задание и не считаются ошибкой. Переходы `cd` на первом и третьем шагах тоже нейтральны. На остальных шагах можно осматривать каталоги через `ls` без штрафа. В `Taskfile` нейтральность задаётся по имени команды (`cd`, `ls`), а не по её аргументам.

Неверная команда выполняется в учебном окружении, но текущая цель остаётся активной. После пяти неудачных попыток появляется одна подсказка:

| Часть | Подсказка |
|---|---|
| `/` | Сначала перейди в корень командой `cd /`, затем выведи его содержимое через `ls`. |
| `/etc` | Этот файл текстовый: открой его той же командой, что `readme_please.txt`. |
| `/home` | Перейди в `/home` командой `cd`, затем выведи содержимое через `ls`. |
| `/proc` | Содержимое этого файла можно прочитать командой `cat`. |
| `/dev` | Подробный вид `ls` ты уже включал знакомым коротким ключом. |

## Критерии приёмки задания

Задание готово к использованию, если:

1. `Taskfile` разбирается штатным парсером без ошибок.
2. Первые четыре цели используют `observe output`, а `/dev/null` — `accept output`; вспомогательных `check exec` нет.
3. Принимается равнозначный результат независимо от текста введённой команды.
4. Теория появляется непосредственно перед новой темой и не раскрывает полный ответ заранее.
5. Подсказки не появляются раньше пятой неудачной попытки.
6. Финальный сценарий существует, имеет исполняемый режим и проходит `sh -n`.
7. `root-tour` находится после `cd-abs` в блоке «Знакомство».

Изменение следует обновлённому авторскому skill проекта. Проверены разбор всех 34 `Taskfile`, пять этапов `root-tour`, положительные и отрицательные примеры вывода `/dev/null`, `git diff --check` и синтаксис `deploy.sh` и финального сценария. Полная контейнерная сборка требует Linux с `systemd-nspawn` и настроенным scoped sudo.
