# Инструкция пользователя

hashpass состоит из двух команд и общего пула:

- **`hashpass`** — студенческая: регистрация на пуле, загрузка и запуск заданий.
- **`hashengine`** — авторская: сборка образов, публикация заданий в пул, запуск самого пула
  (реестр + веб-панель). Привилегированная — активируется только через `make install` или
  установку с сайта пула с ролью автора.
- **Пул** — сетевой сервис (`hashengine serve`): аутентификация с ролями, регистрация, каталог
  заданий по номерам, серверный прогресс, проверка целостности, веб-панель преподавателя.

Полный справочник DSL — в [Авторинг заданий (task authoring).md](<Авторинг заданий (task authoring).md>).

## Требования

- Python 3.13;
- `systemd-nspawn` (пакет `systemd-container`) и `overlayfs` — чтобы запускать задания в контейнере;
- Docker — только автору, для одноразового экспорта базового rootfs `debian:trixie-slim`;
- scoped passwordless sudo на `mount`, `umount`, `systemd-nspawn`, `rsync`, `tar`, `machinectl`;
- пул (`hashengine serve`) — только стандартная библиотека Python, без зависимостей.

Данные и кэш каждой команды: студент — `~/.hashpass`, пул/автор — `~/.hashengine`. Пути можно
переопределить переменными `HASHPASS_HOME` и `HASHENGINE_HOME`.

## Для студента

### Установка

Одной командой — её печатает главная страница пула; адрес пула вшивается в скрипт, вводить его не
нужно:

```bash
curl -fsSL https://<адрес-пула>/install.sh | bash
```

Скрипт ставит команду `hashpass` (в `~/.local`, через `pip install --user`) и записывает адрес пула
в `~/.hashpass/pool.json`.

### Первый запуск — регистрация или вход

При первом обращении к пулу `hashpass` попросит зарегистрироваться (логин, **ФИО**, **группа** —
обязательны) или войти. Токен кэшируется; повторно вводить не нужно.

```bash
hashpass register     # логин + ФИО + группа + пароль
hashpass login        # если аккаунт уже есть
```

### Работа с заданиями

```bash
hashpass              # подтянуть новые задания (параллельно) и показать список по номерам
hashpass run 1        # запустить задание №1 (или `hashpass run <name:version>`)
hashpass pull         # только обновить задания, без запуска
```

`hashpass` без аргументов многопоточно скачивает новые/обновлённые задания из каталога и печатает
их по номерам; пройденные отмечены «✓». `hashpass run <номер>` открывает задание как настоящую
консоль Debian: печатается вступление автора, затем цель этапа; вы вводите обычные команды Linux, а
хост после каждой невидимо проверяет текущий этап. Пройдёте все этапы — результат уходит на пул.

Целостность задания проверяется по хэшу: если файлы задания подменены локально, пул зачёт не
поставит. Ключ зачёта на экран не выводится — он подписывается на сервере (HMAC, привязка к вашему
логину и заданию), списать его неоткуда.

`exit` завершает задание.

## Для автора и преподавателя

### Установка

Из клона репозитория:

```bash
make install       # ставит обе команды и активирует hashengine на этой машине
make uninstall     # удалить
```

`hashengine` работает только на активированной машине (маркер `~/.hashengine/engine.enabled`,
который создают `make install` и установщик с сайта). На обычной студенческой машине команда
`hashengine` откажется работать.

### Команды `hashengine`

- **`hashengine build <Taskfile>`** — собрать образ или задание из одного файла рецепта (формат
  `Taskfile` = `Imagefile`; если есть блоки `stage` — это задание). Требует логин (спрашивается один
  раз, кэшируется); собранный ref получает namespace владельца (`<логин>/<имя>:<версия>`). Имя/версию
  можно переопределить флагом `-t`. Базовый образ `debian:trixie` собирается один раз и
  кэшируется; неизменная пересборка не выполняет шаги заново.
- **`hashengine push <ref> --task <N> --title "…"`** — отправить образ (и его слои) в пул и
  опубликовать задание под номером `N`. Пул при этом сам вычисляет и сохраняет хэш задания. Без
  `--task` отправляется только образ, без места в каталоге.
- **`hashengine serve`** — поднять пул (см. ниже).
- **`hashengine login <registry>`** — вход в реестр/пул, кэширование токена.
- **`hashengine images`** — список собранных локально образов и заданий.

### Пул `hashengine serve`

```bash
HASHPASS_REGISTRY=http://0.0.0.0:8080 hashengine serve
```

По умолчанию пул слушает `127.0.0.1:8080` (адрес задаётся переменной `HASHPASS_REGISTRY`; за TLS и
публичный домен отвечает ваш reverse-proxy). При первом запуске на пустом пуле создаётся
администратор: логин из `HASHPASS_ADMIN` (по умолчанию `admin`), пароль из `HASHPASS_ADMIN_PASSWORD`
или сгенерированный и напечатанный один раз.

Данные пула: `~/.hashengine/registry/` (образы, `users.json`, `catalog.json`, `progress/`,
`config.json`, секрет).

### Веб-панель

Откройте `http://<пул>/` — главная страница с командой установки для студентов. Вход преподавателя —
`/web/login`:

- **Прогресс** (`/web`) — таблица «студенты (ФИО, группа) × задания по номерам», ячейки
  passed/failed, фильтр по группам, столбец «Σ». Доступ: автор/админ.
- **Пользователи** (`/web/users`, только админ) — список пользователей, выдача роли автора,
  открыть/закрыть регистрацию.

### Роли и регистрация

Роли: `student` (по умолчанию при регистрации), `author`, `admin`. Первый пользователь пула —
`admin`. Публиковать задания и поднимать пул может автор/админ; студенты — только регистрироваться,
тянуть и запускать. Админ может закрыть регистрацию (тогда новые `register` отклоняются) и выдать
кому-то роль автора — после чего тот получит доступ к установщику `hashengine` на сайте.

## Собрать своё первое задание

Отдельный каталог и файл `Taskfile`:

```text
image hello-report:1
run mkdir -p /home/student

stage "Запишите слово ГОТОВО в файл /home/student/report.txt"
  solve echo ГОТОВО > /home/student/report.txt
  observe /home/student/report.txt
```

Собрать, поднять пул и опубликовать под номером 1:

```bash
hashengine build Taskfile                                   # соберёт <логин>/hello-report:1
hashengine serve &                                          # пул на 127.0.0.1:8080
hashengine login http://127.0.0.1:8080                      # войти автором
hashengine push <логин>/hello-report:1 --task 1 --title "Отчёт"
```

Студент затем ставит `hashpass` с этого пула, регистрируется и запускает `hashpass run 1`. Подробнее
про `stage`, `variant`, `observe output`, `observe bool`, `allow`/`deny`, `check exec`, `accept cmd`,
подсказки и скрытые грейдеры — в [гайде по авторингу](<Авторинг заданий (task authoring).md>).

## FAQ

- **`hashengine` пишет «не активирован»** — это авторский инструмент; поставьте его через `make
  install` или установщик с сайта пула (нужна роль автора).
- **`hashpass run 1` не находит задание** — сначала `hashpass` (без аргументов) или `hashpass pull`,
  чтобы подтянуть каталог.
- **Зачем Docker** — только автору и только один раз, для базового rootfs; дальше всё через
  `systemd-nspawn`.
- **Как отключить авто-обновление** — флаг `--no-update` или переменная `HASHPASS_NO_UPDATE=1`.
- **Где данные** — студент: `~/.hashpass`; пул/автор: `~/.hashengine`. Переопределяются
  `HASHPASS_HOME` / `HASHENGINE_HOME`.
