В сущности заданий лежит 2 понятия. Задание (task) и этап (stage).
Этапы - это промежуточные действия. То есть, задание состоит из нескольких этапов.

Чтобы пройти задание, нужно пройти все этапы, состовляющие его
Чтобы пройти этап, необходимо, чтобы состояние ФС и/или вывод последней команды соответствовал тому, что было зафиксировано при создании

#### Создание
Для того, чтобы прогрузился интерфейс для создания заданий:
```
sudo ./hashengine.py create author/parent_image:version 
```
author/parent_image:version - это имя родительского образа

Теперь мы можем отредактировать файловую систему так, как считаем нужным. После этого:
```
image update
```

Теперь запустим создание задания:
```
task start
```
Далее необходимо создать этап:
```
stage start
```

Проводим все необходимые манипуляции. По сути - решаем нашу задачу, создаем нужную папку, ищем конфигурацию, ищем строчки из /etc/ и т.д.
Для завершения этапа:
```
stage stop
```

Чтобы добавить выполнение команды после того, как этот этап будет выполнен:
```
action command
```

Например:
```
action echo "Неплохо!"
```

Таких этапов можно создать много!

Для завершения создания задания
```
task stop
```

Далее нужно посмотреть какие файлы на каких этапах изменялись, поправить, если нужно, что учитывать, что не учитывать
```
[11:54:18]ξ cat /.hash/config/stage0.toml
observe_list = [ "/home/", "/root", "/usr/bin/", "/usr/local/bin/", "/etc/",]
exclude_list = [ "bash_history", "*.swp",]

[options]
mode = "Interactive"
fs_analyzer = true
fs_accuracy = 0.7
output_analyzer = true
output_accuracy = 0.7
ignore_date = true
ignore_exclude_list = true

[changes.output]
path = "/.hash/.hash.cmd.out"
is_dir = false
pardir = "/.hash"
hash = "8788897876618812039"
state = "modified"
```

Здесь демонстрируются измененные файлы, а также вывод (changes.output) - соответствует последней введенной команде этапа (stage)

Сохраняем задание:
```
task save
```

Далее достаточно будет просто выйти из системы, задание добавится автоматически

#### Редактирование 
С заданиями можно обращаться также, как и с любыми другими образами

```
sudo ./hashengine.py rm bunnyton/student
```

```
sudo ./hashengine.py edit bunnyton/student
```

```
sudo ./hashengine.py create bunnyton/student
```
Да, так тоже можно :)

#### Hooks
Для того, чтобы обрабатывать те или иные команды до того, как они используются, управлять обработкой вывода команды до получения хэша были придуманы хуки.

#### Добавления задания в production
Для проигрывания заданий в production используется hashpass.py

Чтобы добавить новое задание достаточно в settings.py прописать в tasks номер задания и соответствующий ему образ (и все). Подробнее тут - [Приложение для запуска заданий (Production)](Приложение%20для%20запуска%20заданий%20(Production).md)
